# B1-05 / B1-06 批量角色调整

日期：2026-10-29。承接原账号生命周期中“批量角色”缺口，挂靠B1-05、B1-06、B1-07和B1-12；不是跨租户支持访问或完整B1 Gate。

## 任务卡与业务规则

管理端在用户表勾选1–100个账号，统一替换为一组有效角色；保留原单账号角色编辑和批量状态能力。先展示每个账号的角色、权限、菜单和原始数据范围配置差异，再确认提交。预览是时点信息，不作为授权凭证；保存仍检查全部用户版本和管理员规则。没有新表或迁移。

- 不能批量调整本人；内置管理员的调整仍要求当前操作者是租户管理员，最后管理员保护沿用原领域规则。
- 相同角色账号是NO_CHANGE：纳入版本检查，但不提升版本、不撤销会话、不产生变更审计；整批全为不变账号时不可提交。
- 全部目标必须属于当前租户且唯一，并满足iam:user数据范围（租户全部或主组织集合）；缺少范围、缺少主组织或不适用的范围不放行。角色有效、非空，上限100；任一版本错误或规则失败整批回滚。
- 变更账号提升版本、撤销旧登录会话/刷新令牌并逐个记录USER_BATCH_ROLE_ASSIGN审计，包含前后角色ID与结果版本。审计和业务、幂等记录同事务。
- 同一幂等请求重放原结果，不重新授权或追加审计。返回确认的是该请求结果，页面随后重新加载当前列表。

## 代码与契约

后端 `ism-iam/access/AccessService` 复用单账号更新逻辑，并按用户ID排序处理；租户行锁串行化生命周期写入。`AccessController` 新增：

- `POST /api/access/users/batch-role-impact`：只读整批预览，需要iam:user:manage。
- `PUT /api/access/users/batch-roles`：整批替换，需要iam:user:manage和Idempotency-Key。

公共契约新增BatchAssignAccessUserRoles、AccessBatchRolePreview、AccessBatchRoleResult；前端使用生成类型。用户管理新增独立BatchUserRoles组件，沿用Vue3/Element Plus和现有设计规则。

页面打开时固定目标及版本；角色选择变化使旧预览失效，过时异步响应不能覆盖新选择。网络断开/服务端错误保留原body和幂等键；重试不生成新请求。409/权限错误给出关闭、刷新核对和重新选择路径，不显示虚假的成功。弹窗关闭后原未确认请求仍可重新打开重试；跨浏览器重启的持久恢复不在本子任务。
