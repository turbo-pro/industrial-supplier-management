# 退出责任分派站内通知

## 本轮闭环

退出逐实体分派成功时，向当前责任人投递站内消息，关联 `SUPPLIER_EXIT_ENTITY` 和事项 ID。供应商模块声明通知 SPI，bootstrap 适配消息模块公开服务，不共享消息 mapper。投递与实体分派、申请版本推进、事件和审计共用事务；模板停用、失效收件人、变量缺失或渲染超长均失败回滚。旧版本请求在投递前拒绝，不产生重复消息。

首次分派按租户初始化 `SUPPLIER_EXIT_ASSIGNMENT` / `IN_APP` 默认模板；唯一键解决并发初始化。存在模板时不覆盖租户修改，不恢复停用模板。默认变量仅供应商、申请、事项类型和业务编号，不复制处理说明、证件、姓名等敏感数据。模板可通过已有管理 API 修改，变量需限定在上述四项中。其他渠道尚未接入，不伪造短信、邮件或企业微信投递。

管理端 `/messages/inbox` 补齐个人消息页面、未读总数、单条及全部已读。读取与已读均由后端 `message:inbox:view` 控制当前账号，不因为收到通知而授予权限。页面展示最近 200 条，未读数包含更早消息；读取失败清除旧数据，卸载后废弃旧响应。全部已读须确认。正文采用文本渲染，不执行 HTML。

旧通知是历史记录，不是实时待办。重新分派不会改写原收件人的历史消息，撤回、驳回和结清后的旧消息仍保留；阅读不会完成或放行业务。真正的人工待办聚合、期限、催办、失效任务处理和精准业务定位仍待后续，不混入导入导出异步任务中心。

## 验收

- 完整 Maven integration-test verify 通过，隔离 MySQL 15 项集成回归；新增停用模板导致分派和版本回滚、恢复模板后投递、旧版本重试不重复投递断言。
- 专项通知单测 4 项通过：最小引用正确投递、停用模板拒绝、失效账号拒绝、未知变量拒绝；退出分派单测验证 SPI 调用。
- 管理端类型检查和生产构建通过。消息收件箱契约补齐未读/全部已读响应结构及 401/403/404 错误。
- API 客户端 8 项测试通过。Playwright 技能完成隔离模拟接口页面检查：未读数、全部已读取消/确认、读后按钮禁用、单条已读、403 清除旧消息且不伪装零未读。确认框按钮明确使用中文。模拟接口检查不替代真实后端持久化 E2E。
- 旧库 V25 保持原状，未 repair、未清库、未关闭校验；本轮没有新增数据库结构迁移。
