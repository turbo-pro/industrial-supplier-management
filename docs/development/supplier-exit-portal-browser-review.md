# 退出批准到门户失效：真实浏览器验收

2026-10-22，补齐上一段本地门户回收联动的真实跨端路径。没有新增生产 API、数据迁移、页面或配置默认值，不操作现有开发库。

## 一键入口

`node scripts/verify-reminder-e2e.mjs --portal-exit`

要求 JDK 17+、Docker、Node >=20.19、pnpm 10.17.1 和 Chrome。复用现有隔离 MySQL、随机端口后端/门户/管理端、固定 Playwright CLI、私有临时控制目录、失败中止及最终报告核验。未知或互斥参数仍拒绝。CI 新增独立 `portal-exit` 矩阵场景，证据与其他场景分开；本地通过不代表远端 Actions 已通过。

## 真实路径

- 先运行既有门户注册、登录、身份绑定、域隔离和退出验证，再让门户账号重新登录，保留一条真实有效会话。
- 真实员工 `21006` 从管理端签发另一联系人待使用邀请，通过页面填写原因和依据文件 ID，提交退出申请。校验返回 SUBMITTED、申请人正确且本地事实可审批。
- 同一申请人携有效员工令牌直接尝试自审，必须在独立审批规则处返回 400，不能因为未授权/参数错误而误判为自审保护通过。
- 独立员工 `21007` 具有真实数据库角色/退出复核权限，另一页面登录，确认包含本地账号和邀请影响的审批提示并批准。未模拟身份服务、权限、门户、邀请、退出、财务检查或封存 API。
- 门户身份复核失效；旧令牌重放 401，正确密码重新登录仍被拒；待使用邀请不能兑换。退出时间线显示本地回收真实统计 1/1/1。
- 页面打开封存校验，接口及页面均确认摘要一致、包含三条退出事件，外部回收仍为 NOT_VERIFIED。

## 最终数据库断言

仅一条绑定门户账号，DISABLED，管理/令牌版本各为 1；两次门户登录会话均撤销，只有原基线正常退出产生一条 logout 审计；原邀请 ACCEPTED、新邀请 REVOKED 且撤销人为独立审批人。申请 BUSINESS_CLOSED、创建人与审批人不同；封存含三条事件且由审批人封存；逐账号退出回收审计归属该审批人；三个外部核查任务仍为 DISCOVERY_REQUIRED，整体 NOT_VERIFIED。
