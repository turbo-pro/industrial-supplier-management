# 退出外部访问核查目录验收

V49 为已批准的企业级退出申请增加三个独立的核查渠道：供应商门户账号、外部门禁权限、接口凭证。审批完成本地关闭和证据封存后，在同一事务内创建三条 `DISCOVERY_REQUIRED` 记录；唯一键防止同一申请/渠道重复。任何任务创建失败都回滚本地审批，不留下“已退出但无核查目录”的新结果。

V49 不对历史 `BUSINESS_CLOSED` 记录自动补造任务；历史申请读取时若目录为空，页面明确显示“尚未建立核查目录、外部访问未核验”，不能解释为无外部账号。

管理后台退出流程可读取每个申请的核查目录。API 仅对 `supplier:exit:view` 且拥有供应商数据范围的账号开放，申请必须处于 `BUSINESS_CLOSED` 并有本地结果；跨租户或越权返回未找到。三个任务只表示需要发现实际外部账号或权限，不表示这些资源已存在、已连接或已回收。结果中的 `accessRecoveryStatus` 继续为 `NOT_VERIFIED`，本地证据封存摘要不包括后续外部任务。

隔离 MySQL `B0InfrastructureIT` 验证 V49 迁移、批准后恰好三个任务、状态、跨租户拒绝和清理；管理端构建与 OpenAPI 客户端生成检查通过。当前没有供应商门户身份绑定、厂商协议、连接器、幂等回调、重试及成功回执，因此没有任何将任务标为已完成的接口。后续必须先确定外部账号标识与厂商协议，再扩展任务状态和回收执行，不得根据任务存在推断外部访问已关闭。

V50 增加人工“核查发现”记录：有退出复核权限且拥有供应商范围的管理员，在本地关闭的申请下，逐渠道记录 `PRESENT`（发现待核验账号/权限）或 `ABSENT`（未发现），必须附同租户可用证据文件与说明。每次写入使用任务版本做冲突控制，留下独立事件和操作审计；页面展示历史。证据不应含口令、令牌等秘密。发现结果只是人工调查事实，不触发回收，也不改变退出结果的 `NOT_VERIFIED`。跨租户、跨供应商、旧版本、无效证据均应拒绝。

V50 已在隔离 MySQL 8.0 上执行完整 Flyway 迁移；`B0InfrastructureIT` 16 项均执行且无失败（包括发现记录、版本冲突、无效证据及退出结果保持未核验），管理端构建与 OpenAPI 生成检查通过。核查目录只读查询改用非锁定读取，以避免 MySQL 只读事务中的 `FOR UPDATE` 错误。以上不构成任何外部系统回收验收。

V51 增加三个渠道各自的内部核查分派：有 `supplier:exit:assign` 权限且拥有供应商数据范围的管理员可指定本租户当前有效账号、今天至一年内的可选期限和必填分派说明。变更使用任务版本锁，保留旧/新责任人、期限及操作者的独立事件和审计；管理端展示当前责任与历史。停用/外租户账号、过期版本、非法期限及跨申请任务均拒绝。当前分派不会发送站内通知，也未汇入统一任务中心；责任人须在退出申请的核查目录查看。分派既不改变人工发现状态，也不改变结果 `NOT_VERIFIED`。

V51 已在隔离 MySQL 8.0 上完成迁移；`B0InfrastructureIT` 16 项均执行且无失败，新增断言覆盖有效分派、停用和外租户责任人拒绝、旧版本拒绝，以及退出结果保持未核验。管理端构建及 OpenAPI 生成检查通过。
