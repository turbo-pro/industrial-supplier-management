# B1-02 供应商档案额度执行

任务卡：2026-11-04，接套餐配置发布闭环，依据PRD19 PLT-004-AT-001及package-module-quota既定0非无限、满额保留读取/退出契约。

计量口径：租户内deleted=0的供应商主体档案数，包含DRAFT/ACTIVE/SUSPENDED/EXITED；组织、创建人和当前页面筛选不缩小计量范围。退出保留历史主体，因此不自动释放主体档案容量；不提供物理删除或借停启重置容量。未来合并/归档独立定义。本轮唯一生产建档入口为SupplierService.create，门户注册只绑定已有主体，不重复占主体额度。

执行契约：有效订阅已发布版本的有效启用模块中，SUPPLIER_COUNT取既有max合并规则；缺失和0均无新增容量，无无限容量兼容旁路。先验证原动作/组织数据范围，再锁平台租户及当前订阅/授权、读取供应商当前全量计数，检查并预记下一用量，建档/联系人/审计在原事务中提交或一起回滚。所有写节点统一升级前不得宣称并发硬限制全局生效。上线前应给需要新增的租户配置足够额度，不能用repair/写默认无限额度绕过。

公开边界：common-api只放额度预留及计量读取SPI；supplier只操作自身表，platform只操作自身套餐/额度表。Console只展示总数量和额度，不展示供应商正文。供应商实时读数用于额度查询/降级预检，不把旧计数器当现存主档的全部事实。

验收SQ-01满额/缺失/零/模块或订阅失效拒绝；SQ-02并发仅最后一个名额成功；SQ-03重复/审计失败整笔回滚；SQ-04租户隔离、组织范围不能少计；SQ-05满额仍可查/编辑/停用/发起独立退出；SQ-06实时Console用量/预警及降级预检；SQ-07真实浏览器/真实库、只读/失败/窄屏。范围：common-api/platform/supplier、Console、适用契约与生成类型、专项验证。无DDL。回滚需先停建档写请求、核对计数器；不删除主体或订阅，不改变V25。

## 实现与边界

- common-api新增TenantCreationQuota（必须在调用方写事务中预留）和TenantQuotaUsageReader（可信内部聚合读）两个小契约。supplier提供自己的COUNT，platform不查询供应商表；Console读取聚合时临时切入目标租户隔离上下文并在finally恢复，内部系统读取使用现有system scope，不安装业务授权。此SPI不是公开免授权接口，HTTP继续要求platform:package:view。
- SupplierService原组织/数据范围校验后调用预留；平台以MANDATORY传播加入原事务，锁租户，再以当前锁定读解析最新已开始订阅及历史存在性、已发布版本和有效模块。过期/失效不能回退旧订阅或旧指针。supplier的COUNT FOR UPDATE避免先前一致性快照少算已提交记录。原有唯一键、联系人和审计失败均回滚预留；成功时用真实计数+1同步CURRENT台账，不盲信历史台账。
- 额度查询/降级预览通过供应商聚合读实时计数，包括台账从未写入的存量档案。其他代码保持原台账来源，不能宣称用户、存储、文件、任务/API额度已接入。有效模块过滤在读取和写入限制中保持一致，预警使用避免long乘法溢出的80%阈值。
- 普通建档人员只收到通用额度不足提示，不泄露其他组织的数量或档案。Console新用量区位于订阅计划内，读取已用/上限/剩余、预警/满额；每次刷新先清除旧值，失败不能展示假0或沿用旧数字。该区不提供变更供应商正文的能力。
- 旧套餐未配置SUPPLIER_COUNT时同样无新增容量。发布/部署前先为需要建档的租户配置并分配合适的已发布版本；现有订阅分配API可用，Console分配/升降级确认页面仍待下一切片。没有写默认无限额度、自动补账/修改旧库或关闭校验的兼容旁路。
