# B1-07 账号管理公开入口数据范围一致性

日期：2026-10-29。承接批量角色验收登记的缺口，关联B1-05/06/07/12；不扩展为完整场站或跨租户支持访问。

## 任务卡

范围：IAM账号列表、单账号角色预览/替换、状态、重置密码、登录锁、新建账号，以及批量状态/角色的公开HTTP入口。复用iam:user的租户全部/主组织集合，其他无法确定归属的范围不放行。公共入口在幂等重放前重新校验当前范围，防止通过旧成功回执读取已不可见账号。内部初始化/编排接口保持原可信调用约定，不因列表过滤导致已完成写操作无法构造响应。

无新表、无迁移、无请求或响应字段变化；只修改IAM服务/Mapper/控制器及针对性测试和交接，不混入当前视觉与打印草稿。回滚应用恢复旧行为，历史数据与审计不改写；回滚意味着重新失去本范围约束，不能以清库或repair替代。

## 可独立验收目标

- USER-SCOPE-AT-001：有查看权限但无数据范围时列表为空；主组织范围只返回授权账号及其角色，不返回其他组织、无主组织或其他租户账号。
- USER-SCOPE-AT-002：单账号预览、角色、状态、密码重置及登录锁，对范围外账号拒绝；版本、会话、角色和审计不变。
- USER-SCOPE-AT-003：创建账号的组织范围受控；批量状态/角色含范围外目标时整批不写入。
- USER-SCOPE-AT-004：成功请求后收紧范围，同一幂等键不能再返回范围外账号的历史回执；拒绝重放不改变旧成功事实和记录。
- USER-SCOPE-AT-005：租户管理员全范围、有效组织范围内的正常操作，以及既有管理员/版本/令牌/审计与真实页面闭环继续通过。

## 实现与Review边界

列表在SQL层按主组织过滤，随后只读取可见账号的角色；不先加载全租户账号再由页面隐藏。组织范围使用既有授权加载器展开的后代集合，因此总部组织授权包含下属组织；验证跨场站隔离必须使用同级场站，不能把子组织误当成范围外。首次专项5项失败即源于测试将第二场站建在授权总部下，已改为两个同级场站，未削弱生产授权规则。

所有账号写入口在幂等执行前重新校验当前范围。创建入口另检查成功回执所指账号的当前主组织，避免账号移出范围后用旧创建回执读取资料；拒绝重放保留已提交的历史成功记录。内部初始化与可信编排仍使用原服务约定，未来新增HTTP入口必须复用同一范围检查，不得直接暴露内部全量列表。

无请求/响应字段变化，现有API客户端和账号管理页面继续消费同一契约；不修改他人正在编辑的OpenAPI与生成类型。
