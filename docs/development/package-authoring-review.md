# B1-02 套餐配置与发布闭环

任务卡：2026-11-04，来源B1-02、PRD19 PLT-P003/PLT-006–010。承接已有套餐服务和Console未绑定按钮。本轮目标是创建套餐→配置草稿模块与额度→修正→校验→发布→新租户候选可选；不是整个套餐/计量/订阅包完成。

契约：管理与发布权限分别检查，所有写请求幂等；草稿修改使用乐观锁，已发布不可覆盖；发布事务重验当前模块可用性、锁定版本与父套餐，首次发布将DRAFT父套餐激活，失效父套餐拒绝；已订阅版本不改写。模块从平台有效目录选择，额度沿用既有code→非负整数契约，不声称自定义额度已有计量执行器。校验结果仅对应保存版本，发布仍重新校验。

范围：platform/packageplan、Console组件、OpenAPI及生成类型、专项HTTP/真实MySQL/浏览器与CI，必要文档。无DDL，无用户管理端/打印草稿修改。回滚：回退代码前停止配置写入并核对未知回执；不删除已发布套餐/订阅，不repair或清库。

验收PA-01权限/目录；PA-02创建修正发布及租户候选；PA-03未知结果原键重试、重复编码/版本；PA-04并发编辑/发布、不可变及审计回滚；PA-05失效模块/父套餐发布前重验；PA-06真实页面、窄屏/键盘/只读/空/失败态。以下记录实际验收与Review结果。

## 契约和Review

新增`GET /api/console/package-modules`（platform:package:manage）读取有效模块，`PUT /api/console/package-versions/{id}`（同权限、Idempotency-Key）整体替换草稿名称/模块/额度并递增version。保留原创建/校验/发布接口，发布独立要求platform:package:publish；修正原OpenAPI中校验误要求幂等头、发布遗漏幂等头的问题。仅发布人员可查看保存的配置并确认发布，管理人员必须先校验保存版本；后端均重验。

父套餐状态使用现有库语义DRAFT/ACTIVE，版本使用DRAFT/PUBLISHED。创建/编辑/发布按父套餐→版本锁定；发布读取当前锁定模块和目录，避免事务早期快照在等待编辑完成后放过旧配置。首次发布同事务激活父套餐；后续版本发布不改既有订阅。发布、草稿修改乐观锁竞争只允许一方按原version成功。失效父套餐拒绝后续配置/发布。草稿可移除失效模块、补选目录中的其他模块；发布版只读。

创建/版本创建审计位于原HTTP幂等事务，保持原内部服务调用的兼容性；草稿修改和发布审计随写事务回滚。测试首次使用应用账号创建触发器遇到MySQL权限限制，已改为仅在自建隔离容器以测试root连接创建/清理故障触发器；未调整开发或生产库权限。既有服务层额度回归首次暴露直接调用无TenantContext，与新审计位置有关，移动到控制器原幂等事务后回归通过。

UI采用既有Console组件风格与类型化客户端。未知写结果只保留在内存，锁定body/key、表单和关闭/切换按钮，403不能推翻先前未知提交；重试使用原操作路径、key/body。刷新/退出会丢失本地尝试，须按套餐编码核对后继续。保存后切换已保存版本、修改即废弃旧校验；失败摘要接收键盘焦点。支持375/768/1024/1440宽度，目录表局部滚动。UI首次测试发现忙碌保护拦住保存后的内部选版，已拆开用户选择保护与内部回执应用，回归通过。

额度沿用现有模块grant内code→long模型；UI只写入非负安全整数，防止JavaScript精度丢失，既有已保存配置不能静默舍入覆盖。未构造不存在的额度计量器、模块依赖图、停售接口或外部连接器。全业务额度执行/精确用量回填仍是B1-02待交付子项。
