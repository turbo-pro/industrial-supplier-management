# 租户共享表格列方案验收

## 行为与边界

在原受控列目录和 `ui_table_view_owner` 锁锚点上，以 `owner_id=0` 保留租户共享方案；该值不是 IAM 用户，不能用于登录或代替权限。V44 只新增独立发布权限 `table:view:publish`，不改历史 V37。发布权限不自动授予既有角色，须由租户管理员显式分配。读方案仍须 `table:view:manage` 和对应业务表查看权限；写共享方案还须 `table:view:publish`，后端再次校验注册表键和列定义。个人方案接口及归属规则不变。

每个租户/表最多 20 套共享方案，名称和默认方案在该范围唯一。发布、更新、删除持有同一租户/表共享锁锚点，并使用版本校验；旧版本、重名、未注册列、隐藏必显列或宽度越界拒绝。其他租户不可见；普通用户可选择共享方案并另存为个人方案，但不能修改/删除共享原件。共享默认仅作为个人没有默认方案时的回退；系统列仍可临时选择。发布不改变列表查询、后端字段权限、脱敏或导出。

通用 `PersonalTableViews` 组件接入已有五张台账：供应商、合同、项目、人员和车辆设备。界面区分“租户/个人”，发布者可新建、更新与删除共享方案，普通用户只可使用或复制。旧选择在方案被删除后回退系统列，刷新才获取其他管理员的新方案；没有实时推送。

## 验收证据

- 隔离 MySQL 完整 `-Pintegration-test verify` 回放 V1–V44；V25 原始 checksum 的升级回归保留。真实数据库用例覆盖共享方案同租户跨用户可见、跨租户不可见、普通用户不可改、旧版本拒绝、默认与个人独立及删除后回退。
- 模块单测覆盖发布权限与业务表查看权限双重要求；管理端类型检查/构建、契约生成一致性检查通过。
- 暂未运行真实后端持久化浏览器 E2E；前端构建不等同于手工交互验收。
