# 租户用户、角色、权限、菜单和数据范围

授权链路为“套餐模块上限 -> 租户角色授权 -> 用户角色 -> 后端权限快照”。前端菜单只从后端返回的当前菜单树生成导航，不能替代接口的 `@RequiresPermission` 校验。Console 平台角色与租户角色使用不同表、不同权限命名空间和不同令牌受众。

系统权限和菜单定义由开源版本统一维护；租户通过角色选择权限和菜单，不直接复制全局定义。角色的数据范围按资源分别配置，支持租户全部、组织及全部下级、指定项目、本人负责、本人创建和无权限。用户拥有多个角色时，动作权限取并集；数据范围按租户全部、组织并集、项目并集、本人负责、本人创建的顺序合并。

每个租户初始化时生成不可停用的 `TENANT_ADMIN` 内置角色，首管理员获得全部当前系统权限、菜单和租户级数据范围。普通角色可整体替换权限、菜单和数据范围；菜单授权自动补齐父菜单。修改用户角色后递增令牌版本，现有会话立即失效并要求重新登录。

新建用户必须指定主组织，初始密码只写入哈希并强制首次登录修改。角色、用户、用户组织、权限、菜单和数据范围查询全部携带服务端租户上下文；组织范围会通过闭包表扩展到合法下级组织。

验收要求：首管理员可访问系统管理；普通角色只能获得已配置动作；菜单与动作权限分别控制；组织范围包含合法下级但不包含兄弟组织；跨租户角色、组织和用户 ID 无法授权；角色变化使旧令牌失效；内置管理员角色不能被覆盖授权。
