# 自动续推交接

本任务已按用户要求启用每小时自动续推。保持现有 Vue 3 / Spring Boot / MyBatis / MySQL 模块边界，只读取本轮相关需求与文件，避免每轮重新扫描整个仓库。每次完成有验收证据的业务闭环后提交并推送，不等待逐次“继续”。

## 已完成的最近闭环

- 退出逾期自动催办与租户策略：默认关闭、租户开关与 24–720 小时间隔、管理配置页、五分钟分批扫描、系统身份留痕、事务回滚及多实例限频；参见 [自动催办验收](exit-auto-reminder-review.md)。升级链和失败台账仍缺。
- 退出期限与人工站内催办：期限设置/清除留痕、双版本、当前责任人复核、24 小时限频和投递回滚，退出详情与待办展示逾期；参见 [期限催办验收](exit-deadline-reminder-review.md)。定时自动催办及租户规则配置仍未接入。
- 我的退出待办：当前责任人/处置中申请/未结实体的授权范围查询、分页筛选与页面，重新分派和终态无需同步副本；参见 [待办验收](my-exit-tasks-review.md)。期限和催办仍待接入。
- 退出分派站内提醒与个人收件箱：分派/投递同事务、失败回滚、租户默认模板保留自定义、旧版本不重复投递、未读及已读页面；参见 [通知验收](exit-assignment-notification-review.md)。尚不是人工待办和期限催办闭环。
- 逐实体退出处置：八类本地未结事项的具体记录快照、分页、同租户有效责任人分派、处理说明、双版本冲突、重新核验结清及历史保留；不能手工覆盖实时阻断，参见 [逐实体验收](exit-entity-disposition-review.md)。
- 人员/车辆设备列方案与分页：五表目录受控、资源权限独立、脱敏证件列、必显标识和固定操作、标签/过期请求保护；参见 [资源台账验收](resource-table-views-review.md)。
- 合同限制动作闭环：合同创建/生效分别使用平台固定 CONTRACT_CREATE / CONTRACT_ACTIVATE；限制说明页面与 API 同步扩展，合同终止继续允许退出处置。验收见 [动作接入 Review](entry-action-routing-review.md)。
- 独立申诉与解除审批：证据、独立复核、整改及观察期复查，不改写原限制事实。
- 租户观察期配置：配置页、版本与非法值校验、待审申请快照防下调。
- 企业级正式退出：正常退出/淘汰申请、聚合处置项、重新核验、本人撤回、独立批准/驳回、本地业务关闭结果；待处置申请阻止新增业务，旧直接退出入口停用。
- 企业级限制解释：八类已落地动作、全部限制/观察/退出阻断命中、后端数据范围与查询审计、管理页面。参见 [解释验收](restriction-explanation-review.md)；这是建议性快照，不是业务放行或完整规则引擎。
- 个人表格列方案：受控目录、个人多方案、列显隐/顺序/宽度、版本化更新删除、默认唯一与并发隔离，供应商档案首次接入。参见 [列方案验收](personal-table-views.md)；公共方案、其他表接入及浏览器 E2E 尚未完成。
- 合同/项目列方案：三表默认及名称独立、分别校验业务权限、标签重建、台账分页及过期请求保护，新增项目下拉不污染合同列表。参见 [台账验收](ledger-table-views-review.md)；公共方案及其他业务表继续待接入。
- 企业级共享限制判定：新增业务/准入公开入口与解释页面共用 evaluator，保留当前读、供应商锁与全部命中；旧调用兼容。参见 [共享判定验收](shared-enterprise-restriction-review.md)，尚不是完整范围/版本化规则引擎。
- 受控动作路由：项目新建/开工/复工、合同新建/生效、资源登记/启用/使用、现场签到使用准确动作，保留取消/交接/签退等处置路径；台账区分开工和复工。参见 [入口接入验收](entry-action-routing-review.md)，局部范围尚未开启。

参见 [B7 剩余缺口](b7-review-and-gaps.md)、[正式退出边界](supplier-exit-application.md)、[租户观察期验收](tenant-observation-policy-review.md)。已实现模块不等于完整 B7 全部交付。

## 下一步可安全推进

1. 在已完成企业级共享判定基础上，继续补准确动作上下文、完整受控目录、组织/工厂范围及业务拦截命中记录；不绕开已有企业级限制。旧 generic 调用须先完成入口上下文回归，再开放局部范围。查询审计不替代业务命中台账，再扩展对象类型。
2. 退出逐实体台账、责任分派、个人待办、期限与人工/逾期自动站内催办已接入八类本地业务；继续补升级链、失败台账、档案与关系范围、账号访问回收。已有处理说明、延期或催办不允许覆盖仍未结清的实时事实。
3. 供应商门户身份绑定与回收任务状态模型；没有真实外部协议/凭据时保持未核验或待接入，禁止虚构成功。
4. 持续更新需求覆盖及验收缺口，补齐统一 Gate 回归。
5. 公共能力剩余：个人列方案推广到其他表、租户公共方案；MinIO/S3 实际适配；业务搜索覆盖；审批流程与业务单据完整接入。完整批次状态见 [剩余功能跟踪](remaining-feature-tracking.md)，不是仅推进 B7。

紧急淘汰、强制移交、多级配置流程、专项事故/索赔、归档和局部退出仍有缺口。已有 UI 的类型检查/构建通过不能替代持久化端到端页面回归。

## 开发与验收约束

- 检查工作区，保留所有用户改动。独立且边界明确后再并行，不做重叠文件写入或同工作区并行 Maven 构建。
- 模块单测优先；数据库/跨模块变更使用隔离 MySQL 集成验收：`./mvnw -q -pl backend/ism-bootstrap -am -Pintegration-test verify`。
- 修改接口后生成客户端并构建相关前端；提交生成文件后运行 `corepack pnpm check:api`。
- V25 原始 SQL 已按用户明确修复请求恢复，新增 V41 回填快照列，见 [校验恢复](v25-checksum-recovery.md)。旧记录不改 checksum；其他数据库若使用误修改 V25，仍须核对版本/结构并备份，不能自动 repair、清库或关闭校验。
- 只清理自己创建的临时资源。真实外部依赖、必要权限或高风险数据变更再请求用户介入。
