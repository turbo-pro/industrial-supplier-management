# 退出前财务结清核验

本系统不记账、不发起银行付款、不修改 ERP 付款状态。依据 PRD 的事实源矩阵，财务结清由 ERP 提供；付款完成不等于合同、发票、预付款、质保金、扣款及索赔全部结清，不能跨币种用净余额抵消未结事项。

## 已实现

- `FinancialClearanceGateway` 是只读连接器接口，接收服务端租户 ID 和供应商 ID。连接器负责映射外部主体和覆盖所有未结事项，返回 `CLEAR/OPEN/UNKNOWN`、未结事项数量、核验时间、证据引用。
- 未配置连接器、返回空、异常、状态未知、缺少时间或证据、未来时间及过期结果均阻止退出。未知状态的数量 1 表示一项待核验检查，不表示一笔应付款。
- `OPEN` 必须有正数未结事项；`CLEAR` 必须为零。系统不会依据本地合同金额推算已付款。
- 默认有效窗口 15 分钟，通过 `ism.integration.finance.clearance-max-age` 配置（ISO-8601 Duration，例如 `PT15M`，须为正值）。
- 退出预览和最终退出均调用检查提供者；最终退出仍在原状态变更事务中重新核验。

## 部署影响

默认 `ism.integration.finance.mode=ERP`，不内置真实 ERP 或模拟“结清”连接器。**尚未接入 ERP 时，供应商退出会明确阻塞**，包括本地和 Demo；其他业务不受影响。不得为演示绕过生产核验。

## 人工证据核验模式

无 ERP 的独立部署可显式配置 `ism.integration.finance.mode=MANUAL`（环境变量 `ISM_INTEGRATION_FINANCE_MODE=MANUAL`），不能在 ERP 故障时自动降级。两种模式不可同时提供连接器；多连接器配置会启动失败。

- 档案页“财务核验”提交已上传的证据文件 ID 与核验范围/说明。证据必须属于当前租户且可用。核验须覆盖预付款、质保金、扣款、索赔等，不可仅看净余额。
- 查看、提交、复核分别需要 `supplier:finance:view/submit/review` 权限，并叠加供应商数据范围。V31 注册权限但不自动向普通角色授权；部署管理员须分配经办和复核职责。
- 另一名有复核权限的人批准或驳回，提交人不能自审。已批准可撤销；每次提交、复核、撤销均写审计（含证据/说明/结论），旧审计保留。
- 只有批准且证据仍可用的记录用于退出核验。有效窗口沿用 `clearance-max-age`，从复核时间算起（默认 15 分钟）；过期再次阻塞。待复核或尚有效的批准不可覆盖，须先驳回/撤销或等待过期后重新提交。
- 使用版本号防止覆盖；提交和复核与供应商退出共用供应商行锁，已退出供应商仅可查看历史，不能再确认。
- 这是一份人工核验声明，不是 ERP 付款记录；不发起付款、不修改账务，不提供无证据一键跳过。

端点：`GET/POST /api/suppliers/{id}/financial-clearance`、`POST /api/suppliers/{id}/financial-clearance/review`。前端暂通过文件 ID 引用已上传证据，未提供独立上传控件和核验历史列表，历史可从审计查询。

## 尚未完成

真实连接器的认证、超时、外部供应商映射、证据查询、审计和故障恢复未实现。真实 ERP 接入必须解决核验后新增负债的并发窗口（例如 ERP 结清冻结/截止凭证），不能仅凭 15 分钟快照宣称最终账务结清。阻塞入口暂回供应商档案，不展示不存在的财务台账。

因此本轮是标准接口与安全保护，不是完整财务功能，也不是完整 B7 验收。
