# 供应商门户账号管理与会话回收

## 本段范围

V72 为 IAM 独立门户账号新增管理版本，不改已执行迁移。供应商档案通过既有门户邀请面板挂载独立账号管理组件，支持分页查询、原因确认后停用/恢复、撤销该账号全部会话。没有账号删除、身份改绑、密码重置或修改邮箱；不是完整账号生命周期。

接口均是内部员工认证域 `/api/suppliers/{supplierId}/portal-accounts`，不是匿名门户或 Console 的跨租户入口：

- GET：`supplier:master:view` 与当前供应商数据范围；page 从 1 开始、size 1–100，默认 20；返回用户名、显示名、状态、管理版本、未到期会话数和最后登录 UTC 时间。无密码、哈希、邮箱、令牌或内部角色，no-store。
- POST `/{id}/status`：`supplier:master:update` 与当前供应商范围，显式必填 version、ACTIVE/DISABLED 和非空原因（最多 500 字）。停用和恢复均提升管理版本及令牌版本，撤销全部旧会话；恢复不解除密码错误临时锁。
- POST `/{id}/revoke-sessions`：同写权限、显式管理版本及原因；保持账号启停状态，提升两种版本并撤销会话。仍允许 ACTIVE 账号再次正确登录，若要阻止登录须停用。

未授权动作 403；越租户/越供应商/越范围隐藏为 404；陈旧版本和重复目标状态 409；缺失/负数版本、非法状态及空原因 400。拒绝客户端修改绑定。恢复须供应商 DRAFT/ACTIVE 且无提交中的退出申请；不可用供应商仍允许停用和撤销，以免安全处置被业务门禁阻断。

## 事务与模块边界

供应商模块锁定并校验供应商后调用公共 `PortalAccountAdministration` SPI；IAM 实现强制加入既有事务并拥有账号/会话表，不跨模块引用 Mapper。顺序为供应商→账号→会话，与门户登录的相关锁序一致。对账号进行双重 tenant/supplier 约束和版本更新。

状态、管理版本、令牌版本、全部会话撤销与原因审计同事务。审计失败全部回滚。恢复不能复活旧会话，避免原有“临时停用再恢复”的会话重新生效；已有租户/供应商状态临时阻断语义不变。会话数仅统计未到期、未撤销且匹配令牌版本的记录，不代表租户/供应商业务资格，也不表示实际在线人数。

这是本地已知账号的真实回收能力，不是退出申请自动联动。现有 B7 外部核查目录不被自动标记成功；门禁、ERP、外部门户凭据继续未核验。未消费邀请不随账号停用自动撤销，邀请管理仍独立；不要将停用单账号表述成供应商全部访问已回收。
