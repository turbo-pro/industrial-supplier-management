# 审计、幂等、Outbox 与任务租约契约

## 审计

业务模块通过 `AuditService.append` 追加审计记录，不提供普通更新和删除仓储方法。审计保存租户、实际操作者、代理用户、对象、动作、前后摘要、IP、User-Agent、UTC 时间和 traceId。

摘要在入库前统一清理密码、令牌、Secret、凭据、银行账号和证件号等字段。审计查询、导出和归档自身也必须追加审计；日志和异常不得补写被清理的明文。

## 请求幂等

关键写操作调用 `IdempotencyService.execute`，唯一范围是租户、操作者、操作代码和 `Idempotency-Key`：

- 相同键和相同请求摘要并发执行时，业务动作只执行一次，其他请求复用已提交结果；
- 相同键携带不同请求摘要返回 409；
- 业务动作异常时整个事务回滚，幂等占位不会留下伪成功；
- 保存的响应必须经过敏感字段清理。

## Outbox

业务状态、审计和 `OutboxService.enqueue` 必须加入同一本地事务。事件包含稳定事件 ID、租户、类型、版本、聚合根、UTC 时间、traceId 和受控 payload。默认由数据库轮询发布，不要求 Kafka。

调度节点通过 `claimNext` 领取租约。只有当前租约所有者能确认成功或失败；节点失联且租约过期后，其他节点可以接管。失败按 `next_retry_at` 重试，超过上限进入 `DEAD`。消费者使用 `eventId + consumerCode` 幂等记录，并与消费副作用处于同一事务。

## 异步任务

业务线程在当前租户上下文中提交任务。调度节点跨租户领取时只读取任务元数据和已清理 payload。任务支持领取、续租、超时接管和条件完成；旧节点或租约过期节点不能确认完成。

多节点调度仓储属于受控基础设施，不向 Controller 或普通业务服务暴露。任务和事件错误只保存稳定错误码或脱敏摘要，不保存堆栈、连接地址和 Secret。
