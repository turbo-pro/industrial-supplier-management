# 门户企业资料变更与员工审核

2026-10-23，B3 门户资料协作增量。形成“门户提交 → 员工差异复核 → 批准生效/驳回 → 门户核查”的闭环，并支持申请人撤回。

## 业务与字段规则

- 本轮开放企业简称、行业、国家代码、省份、城市、地址、网站七项；不开放企业名称/信用代码、主体归属、联系人、风险、采购品类、证照或财务修改。主体变更和附件证据流程仍待后续专门设计。
- 原档案和申请值存为不可变 JSON 快照，原因必填。空白统一规范化；国家代码须为两位大写字母；网站为空或有效 http/https 地址且不能包含账号密码。无实际变更拒绝。
- 状态为 SUBMITTED → APPROVED / REJECTED / CANCELLED，均保留记录；驳回或撤回不更新档案，重新申请创建新记录。同一租户、同一供应商最多一条待审申请，由数据库唯一约束和供应商行锁保证。
- 提交必须携带当前企业档案版本和 UUID 请求标识。相同账号、标识、原版本及规范化内容重复提交返回原记录；标识复用于其他内容返回 409。门户网络结果未知时保留原标识并锁定填写内容，可先刷新记录核查或显式重试相同申请，不自动重放。
- 批准同时比较当前档案版本和七项原字段快照。期间发生内部维护或其他版本变更时返回 409，须驳回并重新申请，不覆盖内部更新。批准只写白名单字段并推进档案版本。
- 当前供应商停用/退出或有待审退出申请时不能批准；员工仍可驳回待审申请以保留处理结论。资料申请不属于未结合同/现场资源，不自动阻止退出，也不随退出自动批准。门户受既有状态门禁约束。

## 权限与事务

门户范围完全来自当前会话，无客户端租户/供应商参数；同企业账号可查看该企业申请，只有原提交账号可撤回。员工列表使用 `supplier:master:view` 和主档实时数据范围；审核新增独立 `supplier:change:review`，不自动授予现有角色，管理员须显式配置。门户提交与员工审批属于两个身份域；当前没有同一自然人的跨域关联识别、多级审批或双人签字能力。

公共 PortalWriteGuard SPI 在提交/撤回事务内按租户 → 供应商 → 账号 → 会话锁序重新核验有效状态、绑定及令牌版本，防止过滤器认证后发生撤销仍能写入。IAM 提供实现，供应商模块不依赖其实现类或账号表。员工审核锁供应商和申请，批准时档案、申请终态及审计同事务；审计失败全部回滚。

V75 新增 `sup_profile_change`、待审唯一约束、请求标识约束、历史索引和权限目录。仅新增迁移；旧 V25 及校验规则不变。档案读取接口新增只读版本号作为变更前置条件，其他返回字段仍保持白名单。

## 页面与接口

门户企业档案下提供变更表单、前后差异、原因、状态/审核说明、分页与本人撤回确认；成功提交前后档案均可核查。管理端供应商详情下独立展开“资料变更审核”，展示前后对比和只读权限提示，审核说明必填，批准/驳回均有确认；批准后重新读取主档。

API：门户 `GET/POST /portal/profile-changes`、`POST /portal/profile-changes/{id}/cancel`；员工 `GET /suppliers/{supplierId}/profile-changes`、`POST /suppliers/{supplierId}/profile-changes/{id}/review`。门户返回 no-store。OpenAPI/生成客户端同步，分页每次最多 100 条；没有全局人工待办聚合或自动通知，不将列表当作完整消息/工作流集成。
