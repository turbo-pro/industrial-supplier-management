# 自动催办失败台账验收

## 可独立验收的行为

V43 新增 `sup_exit_reminder_failure`，按租户与事项唯一记录自动催办投递失败。失败时原通知事务已回滚，再用独立事务记录失败次数、安全错误代码及 UTC 时间；不存异常消息、堆栈或敏感业务说明。同一事项重复失败累加次数。下一次自动投递成功时，在消息、催办时间、业务事件、审计的同一事务将台账标为 `DELIVERED` 并记录恢复时间；恢复写入失败也使投递整体回滚，不会显示虚假成功。

管理后端的供应商退出弹窗通过 `GET /api/suppliers/{supplierId}/exit-applications/reminder-failures` 分页展示历史。后端要求 `supplier:exit:view`，并用供应商数据范围验证所查供应商；跨租户或越权不能读取。页面显示当前申请/事项状态，避免把历史失败误认作当前仍待处理。错误代码供管理员排查，原始异常仅在服务端日志中。页面请求具有供应商切换与分页过期响应保护。

注意：数据库整体不可用时，独立失败记录也可能写不进去；worker 会记录服务端错误日志，并在下轮重试，不能声称百分之百持久记录。业务状态改变导致不再符合自动催办条件时，历史失败不会被伪装成已送达；页面会同时显示当前申请/事项状态。当前尚无失败通知升级链或跨供应商集中监控。

## 验收证据

- 隔离 MySQL 完整 `-Pintegration-test verify` 回放至 V43，原 V25 checksum 回归不变。
- B0 真库用例：模板停用时通知/版本回滚且失败台账新增、再次失败次数累加、成功后状态与恢复时间更新、跨租户查询拒绝、重复扫描不重复投递。测试结束清理自建台账记录。
- 供应商模块单测拒绝普通用户伪造后台失败/恢复，并拒绝把包含邮箱或异常正文的字符串存为错误代码。
- 管理端构建及 API 客户端生成一致性检查通过。尚未将模拟浏览器操作当作真实后端页面 E2E。
