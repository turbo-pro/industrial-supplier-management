# B1-09 租户字典继承覆盖管理

2026-11-05任务卡。目标：系统字典继承→本租户名称覆盖→条目标签/排序/启停覆盖或可扩展类型自定义→恢复继承/移除自定义→重新覆盖均独立验收；另一个租户始终不变。页面接已有菜单/system/dictionaries，使用Vue3/Element Plus既定样式。Console不写租户字典。

本轮新增租户字典名称覆盖行、条目覆盖状态墓碑；恢复/移除不物理删除版本，避免恢复后重新覆盖被旧版本命中（ABA）。核心系统条目代码/值不允许改语义，仅标签/排序/启停覆盖；历史已存覆盖不自动清洗。扩展字典不等于增加业务枚举或改变既有业务状态机。有效items继续不返回已移除自定义项，管理专用removedItems显式提供墓碑以便携带当前版本重新启用。

DT-01继承/名称/条目/移除恢复及跨租户；DT-02核心值不变、不可扩展类型、无权限/跨Realm；DT-03ABA、并发、幂等与审计回滚；DT-04V91升级保留覆盖/业务/V25且重复迁移零变更；DT-05模拟UI空/错/只读/未知重试/四宽键盘；DT-06真实管理端双租户继承/覆写/恢复、丢失回执和最终数据库。

范围IAM配置自有Mapper/Service/Controller、V92、独立字典页与路由、契约/客户端和测试。不混入原视觉/打印/规划草稿。回滚须停止字典写入并备份，旧二进制会忽略墓碑标记而错误读出覆盖，禁止直接混版/降级；需前向兼容版本或经审批的数据恢复方案，不能自动删除墓碑、repair或清库。既有迁移文件不修改。

## 契约及Review结论

- 既有条目PUT/DELETE继续以认证租户为唯一归属，新增`PUT/DELETE /api/configuration/dictionaries/{typeCode}/name`。读取返回名称来源/名称修订/管理权限；`items`仅有效定义，`removedItems`是管理用的停用自定义墓碑，不作为业务选项。旧幂等回执可缺新元数据，页面收到回执后另行读取当前定义。
- 类型代码、系统条目代码和值不变。名称、标签、排序和条目启停属于展示配置，不能注册新业务枚举或改状态机。历史覆盖值不自动清洗；若与系统标准不符，需明确恢复继承后再编辑。
- 每租户/字典用名称行作数据库互斥，固定先类型行、再条目行的锁序；读取用事务内一致快照。恢复/移除是状态变更，保留修订；新条目首次覆盖从请求0写到版本1，后续携带实际修订，防止两个首次写入都消费版本0。存量版本（包括0）保持原样，升级后的编辑需重读；不承诺旧二进制或旧在途请求混版安全。
- Review补充了单条目操作后快照：审计记录类型、代码、名称/值、来源与版本，不把整本字典或其他条目写进事件；继承恢复事件能查到恢复后的来源和值。没有宣称保存了升级前全部历史版本或已经提供一键回滚。
- UI有来源/版本、只读、有效空项与移除项、明确恢复确认、固定代码/系统值、未知结果原键原内容重试（后续403也保持未知）、409重读、确认回执与后续读取失败分开；协议异常不显示保存成功。表格局部横向滚动，条目启停与条目业务取值分列。
- 首轮页面构建发现原目录GET契约只有200，类型客户端把错误分支判为never。已补401/403/500契约并重新生成；错误/空/只读/冲突/回执后读失败和两端宽度状态重新验证通过。未把首轮构建失败计入通过。
