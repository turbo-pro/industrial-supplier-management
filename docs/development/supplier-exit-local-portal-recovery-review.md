# 退出批准与本地门户回收联动

2026-10-22，本段把已批准退出与本系统已绑定的门户账号、会话及有效未消费邀请接成同一事务；不接入或宣称完成外部门禁、ERP、第三方门户、API 凭据回收。

## 业务闭环

独立审批仍先锁定供应商、核验申请版本、禁止自审、检查证据及全部本地业务事实。仅批准且核验通过后：

1. 关闭供应商与退出申请，建立本地结果。
2. IAM 经公共 `PortalAccountAdministration.recoverForExit` SPI 按账号 ID 升序、每批 100 条处理该租户/供应商的全部门户账号。原已停用账号也提升管理版本和令牌版本，统一为 DISABLED，撤销全部尚未撤销的会话记录；每个账号审计关联退出申请。
3. 撤销该供应商仍有效的 PENDING 邀请，记录审批人、时间、申请 ID 原因及版本。ACCEPTED/REPLACED/REVOKED 及已过期邀请不改历史；过期邀请仍不可兑换。
4. 新增 `LOCAL_PORTAL_RECOVERY` 退出事件，记录处理账号、撤销会话记录、撤销有效未消费邀请的数量。事件先于封存，所以统计参与既有摘要完整性校验；最终批准审计也包含统计。
5. 原外部核查任务仍建立，整体 `accessRecoveryStatus=NOT_VERIFIED` 不变。这里只能证明本系统已知绑定身份的本地回收，不代表其他外部身份清单已查清。

撤回/驳回不执行永久回收。申请处置中原有实时访问门禁仍生效，但撤回后未撤销令牌可恢复访问。已批准操作不能重复审批，不重复增加版本或审计。恢复供应商状态也不能使已撤销令牌/邀请重新有效；正式重新合作流程不在本段。

## 事务与边界

无新迁移、表或接口。供应商模块只通过公共 SPI 调用 IAM，不读写 IAM Mapper；IAM 方法要求既有事务。统一供应商→账号→会话锁序，与注册/管理依赖的供应商锁协调，禁止过程中注册新绑定。批处理采用 keyset，不因修改状态遗漏第二批或重复第一批。

账号/邀请回收、审计、退出结果、事件、封存和外部核查目录处于一个数据库事务。任何一步失败全部回滚，而不是先踢用户再返回审批失败。会话计数是实际新增撤销标记的记录数（包含已过期但原未撤销的记录），不是在线人数。账号数包含原停用账号，不虚报“新增停用人数”。

本地账号回收只发生在既有退出审批权限边界之后，不新增匿名或 Console 跨租户操作入口。原接口参数、数据范围、审批独立性、财务未知即阻断规则保持；测试显式采用有证据和独立复核的 MANUAL 财务模式，不是 ERP 连接成功。

## 页面与接口契约

审批确认明确告知会停用全部本地门户账号、撤销会话及有效未消费邀请；意见仍必填。时间线以“本地门户回收”展示真实事件统计，不将外部结果标记完成。沿用现有 Vue/Element Plus 页面，仅改提示及事件标签；UI/UX 技能用于不可逆动作的确认信息。

OpenAPI 补充原 review 接口的事务语义并重新生成客户端；无请求/响应结构变更。旧封存记录不回填新事件、不修改原摘要，也不对已完成历史退出追溯执行回收。
