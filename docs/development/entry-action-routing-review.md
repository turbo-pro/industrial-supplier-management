# 业务入口受控动作接入

## 实现映射

| 后端入口 | 共享判定动作 | 条件 |
|---|---|---|
| 新建合同 | CONTRACT_CREATE | 后端固定动作，供应商当前状态及企业级限制核验 |
| 草稿合同生效 | CONTRACT_ACTIVATE | 原合同 DRAFT，目标 ACTIVE，保留版本校验 |
| 新建项目 | PROJECT_CREATE | 服务端读取当前供应商 |
| 计划项目开工 | START_WORK | 原项目状态 PLANNED，目标 ACTIVE |
| 暂停项目复工 | RESUME_WORK | 原项目状态 SUSPENDED，目标 ACTIVE |
| 人员/资产登记 | RESOURCE_ASSIGN | 保留项目所属供应商核验 |
| 人员启用/资产投入使用 | RESOURCE_ASSIGN | 保留人员培训/特种凭证与资源状态核验 |
| 现场签到 | SITE_ENTER | 保留锁后人员、项目、培训与特种凭证核验 |
| 准入创建/提交/批准 | QUALIFICATION_APPLY | 既有 eligibleForAdmission 包装继续使用 |

上述入口通过供应商模块 `eligibleForBusiness` / 既有准入包装接入共享 evaluator，不访问跨模块限制表，也不由页面参数定义动作。项目不能将普通开工当作复工，终态不能重启；项目原状态与版本检查仍按既有契约执行。

合同新建/激活使用 CONTRACT_CREATE / CONTRACT_ACTIVATE，补充为平台控制的动作目录扩展：原 PRD 固定目录未覆盖已存在的合同业务，不把合同误映射为 PROJECT_CREATE，也不允许租户改义。主档启用保持自身生命周期转换核验；绩效等历史处置所用旧查询不擅自改成新增业务判定。没有将尚未接入的寻源、分包或门禁动作伪装成已完成。

## 页面与协议

项目台账将原“启动”按钮分为计划项目“开工”和暂停项目“复工”，后端仍接收原状态变更请求，并根据原项目状态推导动作，不新增 action 请求参数。数据库结构、REST 请求和响应没有变动，本轮无需迁移或改变生成客户端。

此处只完善动作路由，不宣称已经支持组织/工厂/项目范围规则；当前 SPI 没有完整范围上下文，不能开启局部限制。因此，动作名称虽然准确，完整 B7-03 和统一范围判定仍未验收完成。

## 自动化与 Review

- 原项目合同归属校验测试更新为 PROJECT_CREATE 入口；新增正常开工/复工分别传递 START_WORK/RESUME_WORK 并保留写入版本的测试。
- 原受限开工/复工测试增加准确动作及不走 generic 入口的断言；新增取消项目不调用新增业务判定的测试。
- 资源登记、启用、使用及交接测试改用 RESOURCE_ASSIGN 的 mock。交接仍不调用任何受控新增业务动作，原身份脱敏、终态与项目归属用例继续执行。
- 签到测试改用 SITE_ENTER，并增加准确动作及不走 generic 的断言；锁后人员资格、过期培训、重复签到与签退测试保持执行。
- 全 bootstrap 隔离 MySQL 回归继续验证真实限制、解除、观察、退出与现有业务入口。单测 mock 只证明路由和不发生非法写入，不代替实际数据库回归。

首次回归发现资源交接测试在双参数方法中混用 Mockito matcher 与字面参数，已改为两个 matcher，未更改任何生产防护或绕过失败测试。前端验证仍为类型检查/构建，不宣称已完成持久化页面 E2E。旧库 V25 保持原状。

2026-09-27 最终验证：`./mvnw -q -pl backend/ism-bootstrap -am -Pintegration-test verify` 成功，项目服务 8、供应商资源服务 8、签到服务 7 个测试通过，真实 MySQL 集成测试 15 个均无失败/错误/跳过。管理端 Vue 类型检查与生产构建、`corepack pnpm check:api` 通过；REST 契约无漂移，迁移仍为 V1–V37。既有 Node 版本要求与大包警告保留，未修改本机环境。

## 合同动作扩展验收（2026-09-27）

限制说明 REST 枚举、生成客户端、管理端选项同时增加两个合同动作。请求仍为建议性预览，不能替代实际写入时锁后核验；合同写入不接收客户端指定动作。企业级限制对两个新动作仍执行全部生效限制与待退出阻断，WATCH 只警示，未引入按动作放宽规则。

新增受限合同创建不写入、正常生效保留版本、终止不调用新增业务 Gate 的单测，并加强受限生效动作断言。枚举参数化及真实 MySQL 的全动作回归自动包含两个新动作。未变更数据库结构，无需迁移；未改旧库 V25，也不宣称页面 E2E 或外部连接器验收完成。

本轮最终验证：完整 bootstrap `-Pintegration-test verify` 成功，项目服务 10、供应商引用 13、真实 MySQL 集成 15 个测试均无失败、错误或跳过；管理端类型检查/生产构建成功，API 客户端 4 个测试通过。生成客户端与接口枚举同步；既有 Node 版本、大包警告仍保留。
