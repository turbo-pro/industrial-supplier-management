# 门户证照换证与原子替代

2026-10-24，B3 门户协作增量，承接已有受控原件上传和新增证照申请。不改变内部既有提前替代换证的行为；本轮专用于门户换证，并明确后续仍需统一内部换证策略。

## 可单独验收的业务规则

- 从本企业已核验证照详情选择原证，捕获原证ID和版本。原证可以临近到期或已过期，但数据库核验状态必须仍为VALID；撤销、已替代、未核验记录不能作为换证原证。待审期间不延长旧证有效期，旧证到期仍按原规则显示/判断过期。
- 复用同账号/企业绑定的完成上传，一份上传只能消费一次；提交参数 `renewalParentId`、`renewalParentVersion` 必须同时出现，类型须与原证相同，支持证书编号不变的续证。其他企业、跨租户原证不可访问。
- 同一原证至多一条门户待核验换证，由供应商行锁和数据库待核验唯一索引共同保证。重复相同标识/内容返回原申请，不重复提交审计；不同内容重用标识或重复待核验申请返回409，失败不留下孤立新证草稿。
- 提交只创建新证DRAFT、来源及换证快照，不更改原证。拒绝只终结新证与待审记录，原证不变；可以重新上传、重新申请，包括同编号。
- 批准沿用员工独立身份、`supplier:qualification:verify` 及资格数据范围；必须同时覆盖新证与原证，避免组织调整后借新证权限修改旧组织记录。当前锁定读取企业、类型、原证及申请，复核原证状态/版本。原证变更后返回409，须拒绝并重新申请，不覆盖撤销或其他换证结果；拒绝仅要求新证范围，不修改无权限原证。
- 新证须已生效且未过期，提交和批准时各复查；未填有效期按类型规则处理。暂不支持未来计划生效，避免新证尚未生效就替代旧证。
- 批准同事务先将未变更原证标记SUPERSEDED，再核验新证VALID、终结待审状态并写换证/核验审计。任一版本冲突、证号冲突或审计失败，原证、新证、待审槽位及审计全回滚。拒绝可在企业不可用/待退出、原证已变更时继续处置，不能因此放行批准。
- 新旧证和原件均保留。批准不是准入通过，也不解除企业限制；门户不展示内部员工核验意见。

## 页面、契约和数据库

门户详情新增“申请该证照换证”，复用现有上传表单。展示原证编号/类型/版本，类型锁定，必须确认新日期和原件；有未提交输入、原件或结果未知申请时拒绝覆盖，提供明确的清空填写动作。状态/错误提示及本页续传沿用既有能力。

管理端核验前重新读取详情，旧版本不继续弹核验框；关联原证时提示新证生效与门户替代影响。只选择性提交该逻辑，其他未提交管理端视觉改动保留。使用真实后端验证业务，单次模拟503验证详情读取失败不进入核验确认，不以模拟接口宣称业务成功。

V77仅新增 `qua_portal_renewal`，保存原证版本、PENDING/APPROVED/REJECTED及生成列待审唯一约束。不修改V25/V76、不repair旧库。公开供应商门禁新增“锁定以处置”方法，允许拒绝而不绕过批准可用性。

继续使用 POST `/portal/certificate-submissions` 的可选换证字段，没有新的外部工作流、队列或部署组件。门户证照读取新增公开版本号；申请列表增加原证关联字段。OpenAPI及生成客户端同步，ID保持字符串。
