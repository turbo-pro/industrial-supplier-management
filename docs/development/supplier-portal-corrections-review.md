# 门户证照拒绝后的关联补正

2026-10-26，B3 门户协作增量，承接独立对外审核说明。本轮交付拒绝后的关联重提，不将其称为完整准入补正或新的多级工作流。

## 可独立验收的业务规则

- 仅绑定企业的门户来源REJECTED申请可作为上一轮，必须提供当前版本及1000字以内非空补正说明。同租户其他企业、其他租户、内部证照、待核验/已通过申请均不可作为补正来源。
- 每轮新建DRAFT、独立来源记录和新归属上传，上一轮的内容、原件、版本、拒绝结果和对外说明不改写。补正允许修改编号、发证机关、日期及原件，但类型与上一轮相同，仍执行当前类型及企业资格规则。
- 一个上一轮仅能创建一个后续补正，不因后续拒绝而释放。继续补正必须从最新拒绝轮发起，禁止从祖先重复分支。首次申请由服务端确定，补正次数逐轮递增，客户端不能指定根或次数。
- 换证补正的原证ID及原证版本从上一轮服务端关系继承；禁止客户端混传换证参数、更换原证或静默使用原证新版本。原证已变更则冲突，须重新发起换证。提交和拒绝仍保留原证，批准沿用已有同事务原子替代和新旧组织范围复核。
- 当前门户写门禁、套餐模块、账号/企业上传归属、单次消费及同标识幂等继续生效。同标识同内容重试返回原结果；不同标识并发纠正同一来源仅一条成功，另一条409。失败不留下新草稿或消费原件。
- 新草稿、来源、补正关系、可选换证待审槽位及 `PORTAL_CERTIFICATE_CORRECTION_SUBMIT` 审计同事务，审计失败整笔回滚。审计不重复保存说明正文。

## 页面与接口

门户申请历史提供“按审核意见补正”，展示上一轮对外说明并预填白名单证照字段；类型锁定，要求重新上传及填写说明。未提交输入/原件和未知结果申请受到保护，不能被选源覆盖。每轮显示上一轮、补正链首次申请、次数、说明及后续申请关联。

员工详情及核验弹窗显示上一轮、次数与供应商补正说明；详情按既有资格数据范围逐条读取上一轮，链接不能越权。门户不返回内部核验意见、员工身份、上传会话ID或文件ID；旧拒绝原件保留供内部审计，门户原件下载仍仅开放已发布证照。

POST `/portal/certificate-submissions` 增加 `correctionOfId`、`correctionOfVersion`、`correctionNote`，非法参数400，越界来源404，状态/版本/分支冲突409。申请列表及幂等结果扩展可预填业务字段、当前版本和补正链白名单。员工详情增加对应补正字段。继续兼容不带补正字段的旧请求JSON和旧构造器，不新增部署组件。

V79新增 `qua_portal_correction`，以(tenant_id, predecessor_id)唯一索引保证不分支，外键关联当前/上一轮/首次申请。旧迁移和旧库校验不变，无repair。同时纠正上一轮文档/契约中“缺少对外说明返回422”的描述：现有统一参数错误实际为400；业务规则阻断仍为422，不为测试改变生产错误码。

管理端只选择性提交补正字段，既有未提交视觉改动保留；构建和浏览器验收基于当前工作区。
