# 文件存储、分片上传与断点续传

文件模块把业务元数据、上传会话和二进制对象分离。业务表只保存不可猜测的文件 ID；对象键由服务端按租户和 SHA-256 生成，客户端文件名永不参与磁盘路径。`ObjectStorage` 是存储边界，默认 `LOCAL` 实现将临时分片和正式对象放在 `ISM_STORAGE_LOCAL_ROOT`，后续 MinIO/S3 适配器必须实现同一契约，业务模块不直接依赖厂商 SDK。

上传闭环为：初始化会话、按索引上传分片、查询会话恢复进度、提交合并。初始化要求完整文件大小和 SHA-256，服务端返回固定分片大小、总分片数和已上传索引；分片要求 `X-Chunk-SHA256`，相同索引和摘要可安全重试，不同内容返回冲突。提交时必须具有全部分片，服务端重新计算完整文件大小和 SHA-256，通过后原子发布对象。相同租户内相同摘要与大小直接秒传，不跨租户暴露对象是否存在。

单文件大小同时受部署上限和租户配置 `upload.maxFileSizeMb` 约束；默认 100 MB，默认分片 5 MB，会话默认 24 小时。文件读取、上传、下载和管理使用独立后端权限。下载由服务端返回安全的 Content-Disposition 和 `nosniff`，不公开本地路径。写操作纳入租户隔离、幂等、乐观锁和审计。

验收要求：中断后查询会话可得到已上传索引并继续；分片大小、索引或摘要错误被拒绝；缺少分片不能提交；合并后内容与摘要一致；并发旧版本提交冲突；同租户可秒传、跨租户不可秒传；路径型文件名被净化；超出租户上限被拒绝；无下载权限不能读取二进制内容。
