# 准入材料门户协作

2026-10-28，B3 供应商准入增量。本功能通过员工明确发布材料索取，使供应商自助提交准入材料，再由员工采纳进入现有准入流程。不会把内部申请草稿直接开放为门户申请，也不会把上传或采纳等同准入通过。

## 页面及角色

- 管理端“供应商准入 → 详情 → 供应商准入材料协作”：读取该申请最近50条索取记录；拥有准入查看与申请权限、且申请为草稿/待补正时，可选1至5种现有材料类型，填写最多1000字供应商可见说明并确认发布。所选材料名称会明确公开；已有内部文件、备注、预计采购额、准入原因和审核意见不复制到门户。
- 同一申请最多一条OPEN或SUBMITTED索取。员工可以撤销索取，必须另填供应商可见撤销说明；不会自动发布内部审核意见。撤销后保留记录与已提交文件，需重新发布新的索取。
- 门户“准入材料协作”：按当前账号绑定企业分页查看已发布索取及历史。每项提交一份PDF/PNG/JPEG文件（8字节至10MB及租户限制），本次清单全部提交；不允许自行增删类型、不允许传入内部文件ID。选项只来自明确发布的快照。未发布申请、内部审核结果不公开。
- 上传复用QUALIFICATION模块现有受控传输边界，历史技术路径为`certificate-uploads`；准入与证照属于同一套餐模块，共用每账号/企业滚动24小时10/50次初始化额度。上传在本页可续传，刷新不保留文件；提交须使用当前账号完成且未过期的有效文件。
- 原件、补正附件及准入材料共享唯一上传消费账本；已消费上传不能跨业务重复使用。共享内容去重仍允许不同上传独立提交，显示名称来自该次拥有的上传，避免泄露其他文件名。
- 门户提交只将索取置为SUBMITTED，员工准入单仍不变。员工查看文件、确认采纳后，只替换所索取类型对应的文件和提供状态，保留其他材料、必填规则、内部备注等；申请仍为原草稿/待补正，须再走原有提交和独立准入审核。超过5项时可分批索取和采纳，完整必填资料最终仍由原准入提交/审核复核。
- 员工读取按`供应商准入`数据范围；发布/采纳/撤销需`view + apply`。员工文件下载还须`resource:file:download`；独立审核仍需`review`且不能批准本人创建的申请。页面操作能力来自服务端返回的canManage/canDownload，后端每次重新授权。
- 门户按当前租户/企业绑定读取，提交和下载在事务中重新核对会话、账号、企业可用性和模块。企业其他联系人可看本企业已提交材料，但不能使用他人上传提交；同一索取只有首次成功提交的账号能原样重放该提交。

## 可独立验收的状态与并发规则

1. 索取状态`OPEN -> SUBMITTED -> ACCEPTED`，OPEN/SUBMITTED也可撤销为CANCELLED；已采纳或撤销不能重新采纳/提交为新内容。保存申请时的version快照、材料名称和明确对外说明。
2. 发布、首次材料提交和员工采纳均要求准入单处于草稿/待补正且版本与快照一致。内部申请被编辑、提交或审核后，旧索取不能覆盖当前资料；员工撤销旧索取，再按现有申请重新发布。品类规则发生变更时，采纳仍由原准入更新校验最新规则。
3. 供应商提交提供索取version及全部类型对应上传。类型和上传均不可重复；遗漏、额外类型、他人/跨租户/未完成/已过期/已失效文件被拒，失败不留下消费或材料半状态。
4. 索取ID、原始version、当前账号和按类型排序后的同一上传集合可安全重放，返回当前真实处理状态，不重复消费/审计；不同内容、其他账号重放、陈旧版本冲突。成功提交后即使员工已采纳，原样重放也不修改申请。
5. 员工采纳必须核对当前索取version、申请version及当前有效文件。企业/申请锁与直接编辑统一顺序；采纳与编辑只能有一个在同版本提交成功。原有准入更新增加申请行锁，避免品类锁与采纳申请锁交叉竞争；旧版本条件更新保持。
6. 发布、材料提交、员工采纳和撤销均将业务记录与审计置于同一事务。采纳中的材料替换、版本/UPDATE轨迹及全局审计失败全部回滚。
7. 下载按索取及材料类型授权，不接收任意文件ID；输出附件、no-store、nosniff和该次上传文件名，下载前执行文件当前读并记录授权打开审计。审计失败不返回文件流；打开不证明远端已完整收到字节。
8. 两端都有加载、失败和刷新入口。门户在提交结果未知时锁定同一版本/上传集合，允许核查或原样重试，不自动重发。员工发布前说明公开内容，采纳前明确会替换对应文件且仍需准入审核；375px布局与键盘焦点按现有交互约定检查。

## 数据与契约

- V83新增`qua_admission_portal_request`和`qua_admission_portal_item`，请求记录来源申请version、单号快照、发布人、明确说明、状态/version、提交人、幂等内容、UTC创建/提交时间及明确撤销说明；材料只在提交后记录受控上传、文件及自有文件名。
- `qua_portal_upload_use`保留所有历史行和唯一upload_id，qualification_id改为可空，增加admission_request_id及外键，CHECK保证每条消费属于且只属于一种明确业务；准入消费类型为ADMISSION。不是无约束的通用文件绑定表。
- 员工接口：`GET/POST /admissions/{id}/material-requests`、`POST /admission-material-requests/{id}/accept`、`POST /admission-material-requests/{id}/cancel`及按材料类型下载。
- 门户接口：`GET /portal/admission-material-requests`、`POST /portal/admission-material-requests/{id}/submit`及按材料类型下载；使用独立portalBearer身份。
- 门户响应只含索取ID、公开单号、说明、状态/version、公开撤销说明、UTC时间、所选材料类型/名称及本人企业已提交文件名；不输出内部申请ID、文件ID、上传ID、人员ID、内部意见或金额。
- 对外契约与生成客户端同步，具体字段界限见OpenAPI；V25等旧迁移不改动，不repair、不清库、不关闭校验。

## Review结论与工作区

复核了明确发布、公司/账号/数据范围、上传跨用途单次消费、旧申请防覆盖、同版本操作互斥、最新必交规则、文件当前有效性、同请求重放和审计回滚；本次交付无已知阻断项。采纳不证明材料真实有效，仍由员工及后续准入审核承担判断。所有数据库验证均使用独立Testcontainers数据库，未操作旧开发库数据或外部服务。

原有管理端视觉布局和设计系统修改保留，本轮仅提交准入协作、共享上传用途边界、契约与对应验收记录，不将无关页面混入提交。

## 保留的后续范围

门户不能自行创建准入申请、选择采购品类或直接决定准入，不自动发布员工审核意见；目前准入结论需联系邀请方，索取ACCEPTED仅表示材料采纳。多附件/材料目录及文件类型细分规则、补正期限/延期催办、材料与证照自动关联、病毒扫描、PDF预览、统一待办及外部连接器均不在本次已完成范围。不据此宣称完整供应商门户已全部完成。
