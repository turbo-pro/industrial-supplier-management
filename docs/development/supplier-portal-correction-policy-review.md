# 门户补正要求、期限与逐项回复

2026-10-26，B3 门户协作增量。沿用“拒绝后创建独立补正”的现有闭环，增加要求清单、目标期限与可核查的逐项回复，不引入独立工作流服务。

## 可独立验收的业务规则

- 员工使用既有 `supplier:qualification:verify` 权限和资格数据范围，在拒绝门户来源申请时可选填期限和有序要求清单。要求最多10项、每项1至200字，去除首尾空白后不重复。期限不能早于北京时间今天，至指定日期北京时间当日结束；批准或内部来源证照不允许指定这些内容。
- 对外意见、期限、清单、核验结果及发布审计同事务保存；发布后没有改写接口。旧数据默认无期限、无清单，不回填内部意见。发布失败不留下任何局部策略。
- 供应商关联补正时必须按上一轮清单原顺序逐项回复，条数完全一致，每项1至500字；仍须填写整体补正说明和重新上传原件。缺少/空白/超长/多余回复或无来源回复均400，不能仅通过勾选宣称材料已通过。
- 期限为协作目标，逾期仍允许提交并标注“迟交补正”，不自动拒绝、不删除旧记录、不延长或撤销原证，也不自动改变准入或限制状态。过期标记按Asia/Shanghai日期计算，截止当日尚不算迟交。
- 当前未消费的拒绝轮显示是否已逾期；一旦关联新轮，旧轮不继续作为逾期待办展示。提交时固化该轮所据的期限、清单、逐项回复与迟交标记，审计失败整笔回滚且原件可重用。后续新一轮核验的清单与本轮所据快照明确分开。
- 原有企业/租户隔离、模块门禁、唯一后续轮、幂等、原证版本继承和批准时组织范围检查继续生效。清单及回复均按纯文本显示，原始JSON内部字段、内部意见和员工身份不对门户输出。

## 页面、数据库及接口

管理端核验弹窗增加日期及每行一项的要求输入；门户历史/补正表单展示期限、逾期、来源清单并收集逐项回复。员工核验弹窗和详情可查看本轮所据清单、回复和迟交标记。弹窗内容可独立滚动，页头与底部动作保持可达，错误提示可聚焦且失败保留输入。既有管理端视觉改动保留，只选择性提交详情入口与独立组件。

V80为 `qua_portal_submission` 增加期限及要求JSON，为 `qua_portal_correction` 增加来源期限/要求、回复JSON及迟交布尔快照；只使用MySQL已有能力，不增加消息或缓存组件。旧迁移不变，不repair旧库。

既有 POST `/qualifications/{id}/verify` 增加可选 `correctionDueDate`、`correctionRequirements`；POST `/portal/certificate-submissions` 增加 `correctionResponses`。门户/员工读取增加结构化清单、期限、回复快照与迟交字段，门户另提供 `correctionOverdue`；内部JSON不作为公开字段。旧请求缺失数组按空清单处理，兼容旧来源JSON与Java构造器。
