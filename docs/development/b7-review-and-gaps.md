# B7 集中 Review 与后续验收缺口

本轮以 PRD `58-b7-restriction-exit-acceptance.md` 为验收依据。当前实现不是完整 B7，不应对外标记“全部验收通过”。

## 已覆盖的本地入口

| 入口 | 企业黑名单/限期限制 | 观察名单 | 处置操作 |
|---|---|---|---|
| 准入创建、提交、批准 | 阻断 | 不阻断 | 驳回/补正仍可处理 |
| 合同新建、激活 | 阻断 | 不阻断 | 结束/终止仍可处理 |
| 项目新建、开工、复工 | 阻断 | 不阻断 | 暂停/取消/结束仍可处理 |
| 人员登记、启用 | 阻断 | 不阻断 | 停用、离场仍可处理 |
| 车辆设备登记、投入使用 | 阻断 | 不阻断 | 维修、退役、交接仍可处理 |
| 现场签到 | 阻断，且复查人员资格 | 不阻断 | 签退仍可处理 |

均通过供应商模块公开接口，不允许页面参数自行决定资格。审批和新增业务使用供应商行锁；当前读复查限制与供应商状态，签到再锁定人员并重新检查数据范围、项目和凭证。

本轮修复：资源和签到遗漏限制判定、合同/项目激活绕过限制、准入批准未复查限制与自审、限制生效并发时的旧快照风险。

## 退出检查覆盖

合同/项目未结束、人员未离场、车辆设备未交接、现场未签退、质量不符合项/安全隐患未关闭、绩效改进未验收、财务未核验均阻止退出。财务默认 ERP 模式未知即阻断；显式人工模式须证据与独立复核。资产退役不等于交接。

这只表示本地业务退出条件通过，不能宣称外部账号或门禁已经回收。

## 尚未完成及推进顺序

1. 限制规则模型：按工厂/组织、地点、品类、动作的范围判定；人员/设备级限制、规则版本、命中记录和全部原因。本轮企业限制仍是租户内企业级，不支持局部范围。
2. 申诉、独立解除审批、观察期/强制整改解除条件、关联主体识别（信用代码精确匹配与敏感字段授权），禁止姓名相同自动处罚。
3. 正式退出申请与处置项、紧急淘汰任务、高风险强制移交审批。现有档案状态接口不等于这些完整流程。
4. 供应商门户身份绑定与账号回收、外部门禁/账号回收任务状态、幂等重试与失败可见。当前尚无供应商门户账号绑定模型或真实回收连接器，不生成虚构成功回执。
5. 对上述全部入口、租户范围、并发、回调幂等、缓存与审计做 B7 Gate 回归，再进入发布验收。

系统内可实现的规则、申请和任务模型继续按此顺序推进；真实 ERP/门禁连接器需要实际厂商协议、测试环境和凭据。未确定的外部协议不能在代码中假定为已集成。现有项目没有 H5、分包和扫码入口的完整验收，因此也不能宣称全渠道限制一致性已完成。
