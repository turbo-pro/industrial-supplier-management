# 限制申诉（管理后台登记）

入口：风险观察与限制台账中的“申诉”。本轮仅实现管理后台登记与独立复核，不提供供应商门户、自助身份验证或外部申诉人认证。

- 对已批准的黑名单、限期限制或观察记录提交理由及已上传的证据文件 ID；证据必须属于当前租户且可用。已批准但尚未生效/已经到期的记录也允许留下申诉事实，不恢复到期限制。
- 每条限制最多一条待处理申诉，数据库生成列唯一键防止并发重复；已形成结论的申诉保留，可再提交新事实。创建不编辑或覆盖以前的理由和证据。
- 状态 `SUBMITTED → ACCEPTED/REJECTED`，申请人及原限制批准人均不能复核；成立须重新校验证据。带 version 处理，不可重复处理结论。
- **提交、受理及申诉成立均不自动暂停或解除限制。** 成立表示申诉事实复核结论，仍需单独的解除处置，不能当作已恢复业务资格。
- 已撤销记录的在途申诉仍可形成历史结论；不重新生效，不修改任何其他限制。
- 每次提交与结论写审计；限制记录、申诉原始内容、证据引用、处理人/时间和结论分别保留，不提供编辑或删除端点。
- 独立动作权限 `supplier:appeal:view/create/review`，叠加 `supplier:master` 数据范围；V32 注册权限，不向普通角色自动授权。需要区分登记人、原批准人和独立复核人。

## 接口

- `GET /api/supplier-blacklist/{caseId}/appeals?page=0&size=20`：分页历史。
- `POST /api/supplier-blacklist/{caseId}/appeals`：理由与证据。
- `POST /api/supplier-blacklist/{caseId}/appeals/{id}/review`：ACCEPT/REJECT、结论、version。

后端先验证原限制数据范围，再按供应商及限制行锁读取当前记录；不能以路径参数绕过租户/组织范围。文件正文仍走文件授权，不通过申诉接口直接公开文件。

## 验收边界

已覆盖“申诉提交不暂停限制”、独立复核、重复提交/处理、证据校验、租户隔离和审计。前端暂通过文件 ID 关联既有文件，未提供单独上传控件；未新增门户、临时暂停决定、独立解除申请/观察期与强制整改核验、申诉通知和 SLA。原有管理员撤销端点不等于未来完整解除审批，不可将本轮标记为全部 B7 申诉解除验收完成。
