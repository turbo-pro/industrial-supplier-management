# 全局搜索与高级搜索

全局搜索和高级搜索使用同一后端契约。首批纳入用户、组织、文件、打印模板、当前用户消息和当前用户异步任务；后续供应商、资质、合同、项目、安全、质量与限制模块接入时继续扩展 `EntityType`，不另建互不兼容的搜索接口。

搜索条件包括关键字、对象类型、状态、更新时间范围、页码和每页数量。关键字中的 `%`、`_` 与转义符按普通字符处理，不能改变查询语义；空条件搜索被拒绝，时间范围倒置被拒绝，单页最多 100 条。返回项只包含稳定 ID、类型、标题、副标题、状态、详情路由和更新时间，不返回密码、消息收件人、文件存储键、任务请求载荷等敏感字段。

权限采用三层校验：调用者首先需要 `search:global:use`，随后服务按底层对象动作权限逐类过滤，再按 `TENANT_ALL`、组织集合或本人负责等数据范围逐条过滤。没有 `iam:user:view`、`iam:organization:view`、`resource:file:view`、`print:template:view`、`message:inbox:view` 或 `task:center:view` 时，对应类型既不查询，也不出现在 `searchedTypes`；数据范围为 `NONE` 时同样不查询。消息和任务即使具备权限也只搜索当前用户自己的记录。所有查询强制使用当前 `TenantContext`，不接受客户端租户 ID。

高级搜索方案按租户和用户私有保存，名称在用户范围内唯一，支持乐观锁更新、删除和唯一默认方案。设置新默认方案时，旧默认方案自动取消；其他用户和其他租户不能读取、修改或删除该方案。

当前实现使用 MySQL 租户内索引与受控模糊匹配，适合管理系统常规规模。业务数据量达到需要独立搜索引擎的阈值后，可在保持 API、权限与数据脱敏语义不变的前提下替换查询适配器；不得让 Elasticsearch/OpenSearch 成为事实权限源。

验收要求：跨租户数据不可见；缺少底层权限的类型不返回；消息和任务不可看到他人数据；通配符按字面量处理；状态与时间可组合筛选；分页顺序稳定；个人方案名称冲突、旧版本更新和旧版本删除返回冲突；同一用户最多一个默认方案；搜索结果不能绕过字段权限和数据脱敏。
