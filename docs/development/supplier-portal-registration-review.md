# 门户邀请兑换与独立身份

## 本段范围

在 V69 邀请管理之上，V70 新增独立 `iam_portal_account`，以及邀请消费时间/账号和匿名请求限流桶。启用后的 POST `/api/portal/auth/register` 可以原子创建门户身份并消费邀请，管理端历史显示 ACCEPTED（已注册兑换）。不会创建 iam_user、内部角色或刷新会话，不签发任何访问令牌，不批准供应商准入。

这不是完整门户交付：尚无门户注册/登录页面、专用认证与会话、自助资料、账号停用/找回及真实浏览器注册联合验收。不要把数据库中账号 ACTIVE 解释为可以登录现有内部管理后台。

## 身份与模块边界

匿名请求只能提供邀请令牌、用户名和密码。租户/供应商、显示名及邮箱全部来自服务器持有的邀请，X-Tenant-Id、请求中的 supplierId/email 不参与绑定。令牌通过独立窄查询精确匹配 SHA-256 哈希，只返回内部定位，不提供公开预览或租户搜索。

供应商模块维护邀请，平台模块通过公开 `PortalRegistrationTenantGate` 锁定并复核控制面 ACTIVE/READY 及当前已开通 SUPPLIER 模块，IAM 通过公开 `PortalAccountProvisioner` 复核身份域 ACTIVE 并创建账号。各模块不直接访问其他模块的业务 Mapper/表。跨模块创建为同一数据库事务中的同步调用，不使用最终一致事件代替邀请单次消费。

账号用户名在租户内唯一，使用 ASCII 用户名并规范为小写；每个账号固定绑定一个供应商。同租户/供应商/邮箱不可重复创建，跨供应商共享账号或多绑定不在当前范围。重名或绑定冲突不会覆盖已有账号，也不消费新邀请。邮箱来自邀请快照，尚未验证所有权；邀请是持有者凭证，必须由内部邀请方通过可信渠道交付，不能声称注册人已通过邮件验证。

## 原子性与并发

兑换在独立 READ_COMMITTED 事务中运行，锁顺序为平台租户→供应商→邀请→IAM 身份域/账号；阻断停用、退出、待退出处置、到期/撤销/重发替代/已兑换邀请。租户锁后再读取有效模块，避免首次定位查询形成旧快照而错过套餐降级。上下文仅按令牌绑定临时打开，结束和异常都恢复，不安装内部角色权限。

创建账号、标记 ACCEPTED、审计同事务。任何一步失败都回滚；同一邀请并发兑换只允许一笔成功。成功后的重复请求一律拒绝，不用邀请重取密码、改绑已有账号或返回内部令牌。网络结果未知需联系邀请方核查，不宣称当前已有完善的账号恢复流程。

密码复用 IAM 强度规则（12 位起、大小写/数字/符号），并限制 UTF-8 72 字节以匹配 BCrypt 的安全输入范围。存储 BCrypt 哈希；注册命令的 toString 显式隐藏凭证，审计只记录关联 ID，不记录密码或邀请令牌。注册响应 no-store，OpenAPI 的凭证字段 writeOnly。

## 开关与限流

默认 `ISM_PORTAL_REGISTRATION_ENABLED=false`。测试环境显式启用，部署方在身份、渠道和后续认证准备好后才能开启；本轮未修改本地部署环境开关。内部注册服务默认关闭时在任何定位或账号写入前拒绝。

只匿名开放注册路径的 POST；GET 和其他门户/内部业务路由仍按原鉴权处理。Controller 对格式合格请求先执行共享 MySQL 限流，每传输层对端每数据库 UTC 分钟最多 20 次；计数独立事务，业务失败也计数，不因应用横向扩容绕过。只使用 request.getRemoteAddr，不自行相信客户端 X-Forwarded-For；反向代理场景可能多个用户共用同一对端额度，需结合可信代理/网关策略再对外开放。此限流不等于验证码、WAF、网络 DDoS 防护或生产容量认证。过期桶在请求中按批清理，不包含原始 IP。

## 验收与余项

隔离测试涵盖：默认关闭无身份读写、凭证 toString 隐藏；原子兑换/绑定/上下文恢复；独立账号不生成内部用户/角色/令牌；重复、过期、撤销、重发替代、供应商/租户停用及模块未开通拒绝；同邀请双事务竞争；重名冲突保留新邀请；弱密码及审计写入故障回滚后重试；匿名 HTTP 忽略伪造租户/供应商/邮箱，正确门户密码也不能走员工登录；共享对端限流。测试只使用全新 Testcontainers MySQL，V25 升级回放继续验证，不 repair 旧库。

复现：配置 JDK 17+ 和可用 Docker 后，在仓库根运行：

```sh
./mvnw -q -pl backend/ism-bootstrap -am -Pintegration-test -Dit.test=PortalRegistrationIT,PortalInvitationIT,PerformanceMigrationUpgradeIT -Dfailsafe.failIfNoSpecifiedTests=false verify
```

前端只增加 ACCEPTED 的文本状态与能力边界说明，按 UI/UX 技能的“不仅依赖颜色”规则表达。既有邀请模拟脚本补已注册兑换显示，不把模拟记录当作真实注册成功；构建和客户端类型检查另验。后续优先补专用门户认证/实时撤销、注册登录页面及真实联合验收，再接供应商自助业务；外部邮件并未发送。

2026-10-21 最终结果：PortalRegistrationIT 6/6、PortalInvitationIT 5/5、PerformanceMigrationUpgradeIT 1/1，失败/错误/跳过均为 0；默认关闭/凭证隐藏单元用例 1/1。最初 Docker 未运行造成的失败未计为通过，启动既有 Docker Desktop 后完整重跑成功。客户端生成/类型检查及管理端构建通过；模拟浏览器原邀请流程和 ACCEPTED 文本检查通过，375px 截图已检查。构建仍有本机 Node/pnpm 版本与既有大包警告。测试容器与本轮前端/浏览器已回收，既有本地数据库未 repair、清库或关闭校验；没有执行部署开关开启。没有做真实门户浏览器注册或远端 CI 成功确认。
