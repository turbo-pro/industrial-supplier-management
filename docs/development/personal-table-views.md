# 个人表格列方案

对应完整推进计划 B2-07 的个人方案部分。当前接入供应商档案 `supplier.master`，并提供通用列方案 API、受控列目录及可复用 `PersonalTableViews` 管理组件。公共/租户级方案和其他业务表接入未完成，不能将 B2-07 整包标为完成。

## 可独立验收的行为

1. 表格上方选择系统列或任意个人方案；打开配置后调整列显示、顺序及 80–600 像素宽度。
2. 编码、名称必须显示；固定业务操作列不参与方案配置。配置不改变后端权限、返回字段、脱敏规则或导出范围。
3. 新建、更新、重命名、另存、删除方案。每个租户/用户/表最多 20 套，名称去首尾空格后按数据库排序规则唯一。
4. 每个用户每张表最多一个默认方案。设置新默认时旧默认取消且版本递增；不设置默认或删除默认后下一次进入使用系统列，不自行挑选其他方案。
5. “系统列（本次）”只恢复本次显示，不删除或取消已保存默认；取消默认可编辑当前默认方案并去掉勾选后更新。
6. 取消编辑不改变表格或数据库。保存失败保留草稿；版本冲突提示刷新核对，不静默覆盖。保存成功重新载入所有方案版本。
7. 未授权/服务不可用时使用本地系统列，不能影响供应商列表使用。刷新方案可重试。页面切换方案时重建列顺序以避免组件内部列缓存错位。

## 接口、数据和权限

`GET/POST /api/table-views/{tableKey}`：读取受控列目录与个人方案 / 新建。

`PUT/DELETE /api/table-views/{tableKey}/{id}`：版本化更新 / 按查询参数 `version` 删除。

前端客户端源于 OpenAPI。后端需要 `table:view:manage` 及对应表 `supplier:master:view` 权限；列目录目前仅允许 `supplier.master`。不接受 ownerId、tenantId、数据库字段名或客户端定义的表目录。新增表必须在服务注册列目录及对应业务权限，并更新契约和接入测试。

V37 创建 `ui_table_view_owner` 作为租户/用户/表并发锁锚点、`ui_table_view` 保存 JSON 列序列。默认方案生成列唯一键、名称唯一键、版本约束及父子外键防止数据库层冲突。方案写操作先持有锁锚点，配额统计采用当前读，默认变更与方案写入、审计同事务；重复名称、旧版本等失败全部回滚。锁锚点不包含业务数据。

读取、更新、删除始终从 TenantContext 获取租户与用户；不属于本人的 ID 返回 NOT_FOUND，不能借由设置默认改变他人配置。方案对象只有注册列键、布尔显示标记与整数宽度，不能携带 SQL、样式脚本、权限表达式或业务数据。审计只记录方案 ID、表键和操作者，不记录任意名称或业务内容。

## 自动化验收范围

服务单测覆盖非法/重复/未知/必显列、宽度、新建版本、表目录与业务权限、当前用户读取、旧版本更新不清除默认、他人方案不可写、配额、重复名称冲突。

隔离 MySQL 集成覆盖实际持久化与 JSON 回读、默认切换版本递增、重复名称事务回滚保留原默认、更新/删除旧版本拒绝、跨用户跨租户隔离、相同名字可在不同用户/租户使用、两线程同时创建默认仅保留一个、审计及删除后空方案回退。

前端验证包含生成契约、Vue 类型检查及生产构建；暂未新增持久化浏览器 E2E，不能以构建成功代替完整页面验收。旧库 V25 校验和异常保持不动。

2026-09-27 验证结果：新增 7 个列方案服务单测通过；`./mvnw -q -pl backend/ism-bootstrap -am -Pintegration-test verify` 成功，15 个真实 MySQL 集成测试无失败、错误或跳过，隔离数据库实际执行到 V37。`corepack pnpm generate:api` 及管理端类型检查/生产构建通过。第一次集成验证发现 `INSERT IGNORE` 不符合租户 SQL 防护契约，已改为标准 INSERT/重复键更新并重跑全量通过，未放宽防护规则。现有 Node 20.12 版本要求及大包构建警告仍在，未擅自升级机器环境。
