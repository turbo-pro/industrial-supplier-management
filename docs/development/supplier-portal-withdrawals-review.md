# 门户证照申请撤回

2026-10-27，B3 门户协作增量。新增、换证及关联补正申请在 `DRAFT`（待员工核验）时可由原提交账号主动撤回。撤回不代表撤销已生效证照，也不代表准入通过。

## 业务规则与独立验收

1. 只允许当前门户会话的原提交账号撤回；同企业其他联系人可见申请结果，但不能代撤回。其他企业、租户及内部创建的草稿均按不存在处理。后端独立复核会话、账号、企业可用性和 QUALIFICATION 套餐模块，不能依靠页面按钮授权。
2. 必须提供当前 `version` 和1至500字的非空原因；原因首尾空白规范化后保存。只有待核验版本可以进入 `WITHDRAWN`，版本增加一次。已通过、拒绝、撤销或被替代的申请不能撤回。
3. 企业锁与员工审核保持互斥，申请行使用当前读及状态/版本条件更新。若审核先完成，撤回返回409；若撤回先完成，审核失败并回滚其原证替代等副作用，两种结果不能同时提交。
4. 相同申请、原始版本和规范化原因可重复调用并返回原结果；改变原因或版本返回409。撤回证据、换证状态和 `PORTAL_CERTIFICATE_WITHDRAW` 审计同事务落库，审计失败不留下半完成状态。
5. 换证撤回仅将对应 `qua_portal_renewal.state` 改为 `WITHDRAWN`，释放同原证的待审名额；原证状态、版本、文件不变。再次申请必须使用新上传和新提交标识。
6. 原提交请求、原件、材料、上传消费记录及补正链全部保留；不能复用已消费上传，也不退还上传额度。撤回的补正仍是原拒绝申请的唯一后续，不能让原拒绝轮次再次分支。需重新发起独立申请，不支持恢复已撤回申请。
7. 门户申请记录展示撤回状态、UTC时间（页面转北京时间）和原因；不把撤回显示为“历史审核说明未发布”。员工详情同步显示撤回证据，台账支持撤回状态筛选且无审核操作。
8. 确认区域显示证书编号、撤回影响、原因及确认勾选；未发出可取消。网络结果未知时冻结版本/原因，允许刷新核查或原样重试，不自动重发、不切换到其他撤回。确认区域接收键盘焦点，窄屏可操作。

## 持久化与接口

- V82 只新增 `qua_portal_withdrawal`，以申请为主键记录租户、企业、账号、源版本、原因和UTC时间；历史申请不补造撤回记录，V25等旧脚本保持不变。
- `POST /api/portal/certificate-submissions/{id}/withdraw`，请求 `{version,reason}`，响应现有白名单申请对象，增加 `withdrawable / withdrawalReason / withdrawnAt`。
- `WITHDRAWN` 加入员工证照状态目录；门户已发布证照目录仍只含已核验及历史证照，撤回不向该目录发布任何草稿。
- 申请撤回不删除文件，不会取消共享去重文件，不触发外部通知或ERP、门禁等连接器。

## Review与工作区边界

- 复核原提交账号限制、实时会话与模块、版本/状态条件、同请求重放、审核互斥、原证不变、文件消费保留、补正不分支及审计事务回滚；未发现待解决的交付阻断项。
- 核验时间和撤回时间分开，撤回时间按UTC存储/输出Z后缀，页面显示北京时间；内部核验意见不输出。
- 提交只包含本轮业务代码、状态字典单行补丁及契约/验收记录。工作区已有管理端视觉布局、设计系统等改动继续保留；其中尚未提交的主档证照布局字典补上WITHDRAWN兼容项，随其原视觉改动留在工作区，不将整个页面混入本次功能提交。
- 本轮不涉及真实外部服务，也不代表全部B3门户完成。
