# 人员与车辆设备列方案验收

## 业务闭环

- B2-07 个人方案扩展至 `resource.person` 和 `resource.asset`，复用 V37 结构，无需迁移。
- 分别要求 `resource:person:view` 和 `resource:asset:view`，并叠加控制器 `table:view:manage`；当前用户/租户身份只从服务端上下文获取。
- 两表支持个人多方案、默认、另存、版本化更新删除、显示/顺序/宽度调整。编码及姓名/名称必显；业务操作及资产交接入口固定保留，不受列隐藏影响。
- 人员只允许 `idNumberMasked` 列，不能配置原始证件号、密码等未注册字段；显示设置不改变数据权限、导出和入场资格。
- 标签独立组件 key、表格布局 key 保证两表方案不串用；新增分页及页数统计。查询、重置、切换返回第一页，切换清空旧数据、关闭旧表单。
- 列表请求序号与标签双重校验，卸载时废弃请求，旧页响应不能覆盖当前页；失败清空当前数据并显示错误。
- REST 目录枚举扩为五表；补齐两类资源列表 400/401/403 错误契约，生成客户端同步。

## 自动化与 Review

后端列方案单测 10 个通过：新增人员/资产查看权限独立及仅脱敏证件目录断言，扩展必显标识/未知列拒绝用例。完整 bootstrap 隔离 MySQL verify 通过，集成测试 15 个无失败、错误或跳过；扩展两张资源表同名/默认独立、跨表 ID 拒绝、跨用户/租户不可删除、版本化更新删除及与项目默认互不影响。

管理端类型检查和生产构建通过，客户端 4 个测试通过。最初错误契约引用了不存在的响应组件，已改为本项目统一 ApiFailure，重新生成并构建；没有忽略生成失败。既有 Node 版本及大包警告保留。

Playwright CLI 使用独立 `ism-resource-review` 浏览器会话及内存模拟接口，不冒充真实后端持久化 E2E；数据库行为由上述 MySQL 集成测试负责。已实际执行并通过：人员翻至第 2 页、必显标识复选框禁用、隐藏脱敏证件列、操作按钮仍保留、切换资产无人员列串用、切回人员恢复个人默认且页码归零。首次直接操作 Element Plus 隐藏原生 checkbox 超时，改点已检查 DOM 中的可见 label 后核对 checked 状态，并重新执行全部断言；没有绕过页面显隐断言。

本轮不改人员/资产状态机、身份脱敏、培训核验、限制判定或交接事实；不触碰旧库 V25。租户公共方案、其他表推广、持久化页面 E2E 和完整 B2-07 仍未全部验收。

补充浏览器失败与竞态验收通过：延迟人员列表在切换资产后返回，不覆盖资产行或总数；模拟 HTTP 403 后旧资产行清空并显示权限错误，移除模拟拒绝后查询恢复。此处只证明前端处理，不证明实际权限配置。
