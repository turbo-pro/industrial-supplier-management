# B1 订阅有效期与未来切换

## 已实现

订阅按 UTC 的 `[effectiveFrom, effectiveTo)` 判断，结束为空表示无固定结束。每次请求解析已到起始时刻的最新有效候选，再检查结束时间和发布状态；到期或版本失效不回退历史套餐。菜单、动作/字段权限、数据范围、模块检查、额度查询及 Console 租户列表/详情共用平台内的有效版本解析。公共管理能力仍保留，历史数据和角色授权不删除。

未来计划在生效前不改变现有能力；下一次分配取代所有尚未生效的计划。原订阅的自然结束时间不被计划提前截断，推迟计划不会意外造成断档；原订阅本来就先到期时，则到新计划开始前没有业务套餐。新套餐到期也不会自动续订或恢复旧版。

分配在租户行锁下执行，取得锁后使用数据库 UTC 时钟，避免多实例机器时间偏差；V66 新增分配序号和有效期查询索引，同毫秒写入时按序号消除随机 ID 排序歧义。过去起始时间按当前时刻立即执行，不追溯修改历史。结束时间必须晚于起始和当前时间。例外配置当前未实现，非空提交明确返回 422 而非静默忽略。

降级预检同时核对旧限额、新限额和已记录用量代码；即使原订阅已经到期、旧限额为零，也不能借续订绕过目标额度低于已用量的拒绝规则。用量来源仍是既有额度台账，并不等于所有业务的用量计数均已接入。

只有完全没有订阅历史的旧租户才兼容读取旧版本指针；首次分配会在同一事务中补建原订阅。已有订阅但已到期或被终止时不会退回指针。数据库 `plt_tenant.package_version_id` 保留最近分配指针，不能直接当有效版本使用；Console 响应已改为解析后的当前版本，可能为空。ACTIVE 表示未撤销的候选记录，不保证此刻正在生效。

本轮不依赖调度进程，不增加部署组件。到达时间边界后由下一次请求直接反映，无需后台任务成功才生效。

## 验收设计

隔离 MySQL 覆盖：旧租户未来分配不提前开通、推迟/替换计划、目录与额度/租户详情一致、非法时窗和例外拒绝且无写入、进入新时窗、到期不回退仍无固定期限的旧版、到期续订恢复。原套餐、IAM 授权和 V25 升级全组一并回归。时间推进只调整本测试创建的隔离记录，不等待真实时钟或修改本地旧库。

OpenAPI 与生成客户端同步 UTC 语义。此增量复用已有分配接口和租户读接口，没有新增可视化日历或订阅历史页；真实 Console 浏览器操作待独立验收。

2026-10-17 最终结果：B0InfrastructureIT 22/22，PerformanceMigrationUpgradeIT 1/1，失败/错误/跳过均为 0；客户端重新生成及 `tsc --noEmit` 通过，`git diff --check` 通过。最后一轮包含到期续订的超用量拒绝场景。V25 校验和保持原值，没有 repair、清库或关闭校验。Review 核对了有效版本唯一解析、到期不回退、旧租户兼容、未实现例外不静默成功、事务分配及时间精度排序；真正并发分配及真实浏览器流程仍需独立验收，不将顺序替换测试当作并发验收。

## 仍缺

完整模块依赖图、计划列表/取消入口、例外授权、到期预警消息、历史旧数据异常时窗的人工审查，以及配额真实用量的全业务闭环仍需后续推进。套餐版本 `effective_from` 仍是版本元数据，租户能力以订阅起始时刻为准。计划时校验当前用量；计划生效时不删除超额数据，新增额度检查按新限额拒绝。不能将本轮标记为完整 B1 完成。
