# 逐实体退出处置与责任记录

## 范围与实体模型

在原 B7 企业级正式退出基础上新增 V38 `sup_exit_entity`，不改历史迁移。合同、项目、人员、车辆设备、安全隐患、现场签到、质量不符合项、绩效改进八类本地检查通过各业务模块公开 SPI 提供具体记录 ID；供应商模块不访问其他业务表。

原 `sup_exit_item` 汇总检查保留，财务未知、外部访问未核验和缺失能力也保留。实体快照与八类汇总数量不一致、重复实体、非法类型或 ID 时失败，不能因此静默放行。财务和外部账号尚无真实实体协议，不生成假明细。

核验模块缺失时，仅更新缺失能力的阻断汇总，不清除该类型原有实体事实；历史实体状态仍是上次有效核验快照，不能将未知当作结清。数据库清除操作限定本次实际提供有效汇总的类型。

每个申请/检查类型/业务 ID 唯一。记录核验状态、责任人、处理说明、分派人/时间、最后核验时间、结清时间和版本。首次/重新核验及最终批准重新读取业务事实；不存在于未结事实中的历史实体标记 CLEARED，保留责任及说明。仍未结或重新出现的实体保持/恢复 OPEN，不覆盖历史原业务凭证。

## 可独立验收的业务行为

- 退出详情同时展示汇总和逐条记录；提供对应业务台账入口，但没有声称精准定位业务详情页面。
- 申请响应只内嵌前 20 条明细及总数，独立明细接口按页读取、最大每页 100 条；展开后支持分页。明细页带当前申请版本，过期页面要求刷新，切页序号/供应商/弹窗状态共同保护响应，失败不沿用上一页数据。
- 权限 `supplier:exit:assign` 单独控制责任/说明变更，必须通过供应商当前数据范围；读取仍需原退出查看权限。实体只含业务记录引用，不包含人员姓名、证件、财务或其他跨模块敏感字段。打开业务台账后，其权限和数据范围继续独立生效。
- 责任人只接受同租户、ACTIVE、未删除账号，IAM 当前锁读经公开引用服务提供，bootstrap 适配 SPI，避免供应商直接依赖 IAM mapper 或形成模块循环。
- 分派带申请和实体两个版本；并发旧页、错用申请/实体、申请终态或实体已结清拒绝更新。分派前重新读取当前未结事实，已经业务结清但旧页面仍显示 OPEN 时要求重新核验。
- 分派只更新责任和说明，并推进实体/申请版本，保留申请事件与审计。没有完成标志，也不授予责任人业务权限。处理说明不能覆盖未结合同等实时事实，批准仍走原独立审批及全部强制核验。
- 页面支持填账号 ID/分派给我；不为方便下拉而泄露 IAM 全用户目录。仍未实现账号选择器、截止日期、任务中心提醒或强制移交。
- 核验结清后保留记录、分派信息和说明，禁止编辑终态申请。外部回收结果仍为 NOT_VERIFIED，不等于完全清退。
- 退出弹窗增加 supplier ID / 打开状态 / 请求序号保护，关闭或更换供应商后废弃旧查询结果；查询错误清空旧数据而不是伪装成功。
