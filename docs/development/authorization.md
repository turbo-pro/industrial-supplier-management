# 后端权限、数据范围与字段保护契约

## 判定顺序

业务接口按以下顺序执行，任一步失败即停止：

1. JWT 身份和租户上下文；
2. 套餐与模块授权（B1 接入）；
3. `@RequiresPermission` 动作权限；
4. `PermissionGuard.requireData` 数据范围；
5. 字段明文、掩码、拒绝或不返回策略；
6. 业务状态、幂等、事务和审计。

前端菜单和按钮只用于导航与操作提示，不能替代后端权限。`manage` 不隐含批准、导出、打印或敏感字段查看。

## 权限快照

`AuthorizationGrantLoader` 按租户和实际操作者加载 `PermissionSnapshot`。当前默认实现返回空权限，确保尚未接入 B1 角色数据时不会意外放行。B1 实现需要合并套餐、租户开关、角色、临时授权和拒绝规则，并保持结果可解释。

权限上下文与请求生命周期绑定，请求结束自动清理。Console 平台角色不能直接转换为租户业务权限。

## 数据范围

统一支持租户全部、指定组织、指定项目、本人负责、本人创建和无权限。列表查询应把同一范围转换为 SQL 条件；详情、修改、附件、搜索、统计、导出和打印仍必须使用同一 `PermissionGuard` 复核。数据无权访问统一按不存在处理，避免通过 ID 判断其他范围数据是否存在。

禁止把前端传入的任意 SQL、表达式或组织 ID 直接作为数据权限规则。

## 字段保护

`SensitiveDataMasker` 提供手机号、邮箱、证件号、银行账号和 Secret 的统一策略。S2 字段没有明文权限时返回掩码；S3 Secret 没有权限时不返回值。高级搜索、导出、打印、消息变量、日志、错误详情和审计摘要必须复用同一字段权限语义，不能通过其他出口获得明文。
