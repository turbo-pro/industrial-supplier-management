# B1 数据范围资源套餐约束

## 业务规则

V65 新增 IAM 所有的 `sys_data_scope_resource_module` 目录，明确登记现有 16 类数据资源的模块归属。可选目录不再从租户历史授权反推，因此无需先给其他角色授权才能选到新资源。SYSTEM/COMMON 公共资源保持可用，其余按平台公开接口返回的当前已开通模块过滤。

供应商主档资源 `supplier:master` 同时供 SUPPLIER 和 RESTRICTION 使用；任一模块开通即可配置数据范围，但不会因此获得另一个模块的操作权限。其它资源分别归属准入资质、合同项目、人员设备、安全、质量、绩效模块。新增资源必须通过新增迁移登记，不允许依赖任意字符串或权限前缀推断。

角色授权保存对未知或未开通资源返回 422，权限、菜单、范围及版本整笔回滚。每次权限加载也过滤数据范围及其组织子树，未开通或未登记资源按 NONE 处理。套餐降级不删除历史授权，角色详情仍供追溯；再次开通恢复其效果。目录不是最终数据访问许可，仍须同时通过操作权限和业务记录范围检查。

## 验证

隔离 MySQL 的 B0InfrastructureIT 覆盖目录开通/关闭、管理员有效范围随套餐变化、未开通和未知范围提交 422 与整笔回滚、历史未知范围不可生效及独立 RESTRICTION 共用主档范围但不获得主档操作权限。PerformanceMigrationUpgradeIT 从原始 V25 升级并校验其校验和保持不变。执行结果见推进记录。

接口结构不变，管理端现有资源选项直接消费过滤后的目录；OpenAPI 描述及生成客户端同步。未触碰本地既有数据库，也未 repair 或关闭迁移校验。

2026-10-17 最终执行结果：B0InfrastructureIT 21/21、PerformanceMigrationUpgradeIT 1/1，失败/错误/跳过均为 0；API 客户端生成与 `tsc --noEmit` 通过，`git diff --check` 通过。首轮目录查询被租户隔离拦截器拒绝，已补租户参数及绑定谓词后重新执行全组通过，未绕过隔离检查。Review 核对了共享范围不扩大操作权限、原授权追溯保留、异常事务回滚与模块存储边界；独立浏览器流程尚未验收。
