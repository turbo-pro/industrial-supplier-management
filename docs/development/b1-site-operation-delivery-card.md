## 建卡时的差距（实施前基线）

`TenantService.initialize`固定创建HEADQUARTERS根节点，并将首管理员组织及当前上下文设为总部；没有运营模式。`OrganizationModels.CreateOrganization`要求parentId，当前服务无法创建独立根场站。`OrganizationService.switchTo`只更新用户当前组织；候选组织按用户组织的后代判定，包含总部和部门，不能等同经营场站。`current`还没有停用场站处理。现有TenantContext与认证入口没有独立场站上下文，不能把顶部组织切换器写成SITE-AT-004完成。

## 依赖顺序与可验收切片

1. **SITE-INIT / B1-03/04**：Console初始化显式选择SINGLE_SITE或MULTI_SITE及称谓；单场站创建根SITE，不创建总部；多场站创建总部与至少一个SITE。首管理员、组织闭包、组织映射及默认场站必须同事务成功，失败可重试且无半初始化。API/客户端/Console页面/隔离数据库闭环共同交付，覆盖SITE-AT-001、007及012涉及的初始化部分，不标整条场站验收完成。
2. **SITE-UPGRADE / B1-04**：单转多新增总部、重挂原场站并维护闭包；原场站ID/编码及所有历史引用不变。双客户端版本冲突和幂等重放纳入验证；不提供多转单。覆盖SITE-AT-008。旧租户必须有结构预检和明确转换方案，不得将所有既有总部静默改成SITE，或清理已有业务来凑合法结构。
3. **SITE-CONTEXT / B1-07/12**：IAM公开场站读取契约，候选必须是有效SITE且通过授权；默认/最近偏好不授予权限。单有效场站自动进入，多场站搜索/切换；服务端签发的上下文绑定租户、用户和场站，每次使用复核当前授权与状态。与现有组织上下文分开建模，单独设计总部视角，不能将总部ID填入场站字段。覆盖SITE-AT-002/003/005，联合停用/撤权/过期/跨租户反例；各业务尚未接入时不对外声称切换即全局隔离。
4. **SITE-BUSINESS / B1-07与相关业务包**：按PRD数据归属逐类接入项目、培训、入场、门禁和检查等；列表、详情、搜索、统计、待办、消息、导出、打印、新增和附件逐入口验收。必须归场站的业务拒绝总部/法人/部门节点；停用后历史按权限可查，新业务拒绝。供应商主体继续租户级，合同合作关系继续法人/采购组织级，不能统一增加site_id后盲目过滤。覆盖SITE-AT-004/006/009。
5. **SITE-HQ / B1-06/07/12**：汇总、明细、编辑、敏感字段、规则发布、跨场站导出分权；集团默认模板与场站允许覆盖项保留发布版本/影响范围/历史引用。覆盖SITE-AT-010/011，与配置版本及业务模块依赖联合验收。

## 修改范围与门禁

先实施SITE-INIT：新增向前迁移、platform租户初始化、IAM公开组织契约、Console初始化页面、OpenAPI与客户端、专用真实HTTP/数据库测试和真实页面验证。不能从platform继续新增对IAM内部Mapper的依赖。现有跨模块初始化SQL是已知历史边界，新增逻辑应通过公开应用契约收敛，避免新建第二套组织写入规则。

兼容性先核对现有初始化调用、演示种子和自动化夹具；旧请求不能静默得到“多场站已完整开通”的假象。迁移只扩展元数据，不臆测旧租户运营模式，不修改业务归属。旧租户结构分类和历史数据处理未验证前保持可识别待处理状态，不能把未分类解释成已授权全部场站。具体兼容契约在实现前写入专项，不以默认值掩盖缺口。

数据权限仍以当前角色授权为准；组织成员身份、组织树可见性、偏好选择和套餐菜单均不能替代操作/数据/字段权限。Console支持访问另依PRD68，不因总部上下文获得跨租户能力。

回滚：应用回退前检查新模式租户是否已创建，旧应用若只能解释总部根结构不得直接接管；先停止相关写入并按数据库备份/应用版本成对恢复。禁止自动逆向迁移根节点、删除场站、改业务ID、repair V25或关闭校验。每个切片提交前记录实际迁移、回滚条件和证据。
