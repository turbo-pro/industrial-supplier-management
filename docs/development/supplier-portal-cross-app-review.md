# 门户账号管理真实跨端验收

2026-10-22，补齐管理端操作→门户实际失效的浏览器与数据库联合验证。没有新增生产接口、页面、数据库迁移或部署开关，没有触碰用户尚未提交的管理端样式与设计文件。

## 一键复现

JDK 17+、Docker、Node >=20.19（推荐 22.14）、pnpm 10.17.1、Chrome 可用时，在仓库根目录执行：

`node scripts/verify-reminder-e2e.mjs --portal-management`

执行器为本轮创建独立 Testcontainers MySQL、随机后端与两套 Vite 端口。`PortalBrowserFixture` 显式管理场景初始化两个真实员工、BCrypt 密码、组织归属和数据库角色/权限/范围；不模拟 AuthService、授权加载、会话或业务接口。普通 `--portal` 场景仍不初始化员工。无参数继续运行原 Console 提醒场景；未知或互斥参数直接失败，不悄悄跑错场景。

## 验证链

1. 先完成既有门户邀请注册、错误密码、登录、身份绑定、跨认证域拒绝及退出/重放验证。
2. 门户再次登录。真实员工通过管理端页面、填写原因并确认停用该账号，门户“重新确认身份”返回失效；正确密码此时也不能登录。
3. 管理端恢复账号。已撤销旧令牌仍返回 401；门户新登录成功。
4. 管理端撤销全部会话。门户再次失效，但新登录仍可成功，最后正常退出。
5. 第二个真实只读员工登录管理端，只能查询；页面无停用按钮，直接向写接口提交合法版本和原因也返回 403。
6. 最终数据库断言：一条绑定门户账号、邀请 ACCEPTED；四条门户登录会话全部撤销、登录审计四条/退出审计两条；账号 ACTIVE、管理与令牌版本均为 3；三条管理审计均归属于真实写入员工；内部员工数量仅为测试初始化的两条，门户密码失败计数已清零，会话保存哈希而非明文。

浏览器、Maven 和最终夹具报告三者均通过才认定成功；浏览器完成不代表数据库断言已经通过。固定 CLI 0.1.22，测试邀请在权限 0600 控制文件中传递，不写 URL 或输出完整带凭证脚本。日志与截图保留，退出仅清理自己的临时控制目录与进程组；测试数据库由 Testcontainers 回收。

- 原应用中未提交的 UI 改动仍保留。选择器基于两种布局共有的登录表单、账号管理区域和状态提示，不依赖未提交的账号菜单；本地截图体现当前工作区样式，远端干净检出的 Actions 结果需另行核对。
