# 企业级限制业务门禁命中台账验收

B7-02/B7-03 增量：V46 新建独立 `sup_restriction_gate_hit`，由实际业务入口经 `SupplierReferenceService.eligibleForBusiness` 调用共享 evaluator 后记录 WARN/DENY 命中。每个命中只保存租户、供应商、操作者、固定业务动作、命中类型、稳定来源 ID、业务日期和判定时间；不保存原始限制原因、人员证件或任意请求文本。ALLOW 无命中不写行，解释接口只写原查询审计、不进入业务命中台账。部分旧入口仍为 `GENERIC_NEW_BUSINESS`，不能借台账宣称已完成全部准确动作路由。

业务拦截通常导致外层事务回滚，因此台账使用独立事务落库，不作为业务放行凭证，也不表示业务动作成功。记录失败时业务请求失败，避免出现“无命中记录却继续放行/拒绝”的静默缺口。台账按供应商分页读取，沿用 `supplier:restriction:explain` 权限及供应商实时数据范围；限制解释弹窗提供入口。不存在或越权供应商不读取台账。

验收：单测核对固定动作及稳定字段、不保存解释文本、不可见供应商与非法分页先拒绝；隔离 MySQL 集成测试确认外层业务事务回滚后命中仍保留、解释查询不产生业务命中、跨租户与数据范围受控。读取接口由后端 `supplier:restriction:explain` 注解权限保护。后端完整回归、管理端构建和 OpenAPI 生成一致性为 Gate。

验证记录：完整 Maven `-Pintegration-test verify` 通过；补充的 B0 定向复跑中，一次在既有财务人工核验时间敏感断言（第 444 行，进入本次新断言前）失败，原命令再次复跑 15/15 通过。未放宽财务阻断或修改旧迁移，后续单独排查该测试稳定性。

未实现组织/工厂/项目局部范围、人员设备级规则、完整动作上下文或统一版本化规则引擎。该台账记录的是企业级门禁检查结果，不是完整业务审批或外部系统回执。
