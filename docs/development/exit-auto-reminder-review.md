# 退出处置自动催办与租户策略验收

## 业务行为

V42 新增租户配置 `exit.autoReminderEnabled`（默认 0，须租户主动开启）和 `exit.autoReminderIntervalHours`（默认 24，允许 24–720 小时）。管理后台现有租户配置页提供开关与间隔，沿用配置 API 的 `system:setting:view/manage` 后端权限、租户隔离、版本冲突与幂等键；启用时先保存间隔，停用时先关闭开关。单项失败提示刷新，不声称两项是原子设置。

后台每五分钟扫描一次，每轮最多十页、每页百条，按 ID 游标跨轮继续，避免失败事项永久挡住后续事项。只候选“申请仍待审、事项 OPEN、已分派、期限早于 Asia/Shanghai 当日、至少 24 小时未催办、租户显式启用”的记录。每笔在独立事务内重新锁定租户开关、供应商、申请和事项，核对当前有效责任人、真实未结业务与租户间隔；多实例抢同一事项由供应商行锁和版本更新串行化。发送复用 `SUPPLIER_EXIT_REMINDER` 站内模板；消息、提醒时间、双版本、系统事件和操作审计同事务提交或回滚。自动事件的 actor/operator 为 `0`，与人工催办区分；不借用责任人身份。

部署可用 `ism.exit.auto-reminder.worker-enabled=false` 停止扫描；即使启用 worker，租户默认仍关闭。自动催办只提醒，不改变业务处置结果或访问回收状态。当前无升级链、短信/邮件、组织时区自定义和统一跨业务任务中心；后续已补 [自动催办失败台账](exit-reminder-failure-ledger-review.md)，模板失效等失败可在供应商退出页面查看并等待下轮重试。

## 验收证据

- Maven `-Pintegration-test verify` 在隔离 MySQL 回放 V1–V42；原始 V25 checksum 回归继续通过，B0 15 项与旧库升级 1 项无失败。
- B0 真库用例覆盖默认关闭、模板停用后消息/版本回滚、租户间隔 48 小时拒绝 25 小时内重发、24 小时配置成功、重复扫描不重发、关闭开关后不重发、事件与审计系统操作者为 0。
- 单测覆盖配置非法值、逾期与当前事实复核、普通用户不能调用系统自动入口。管理端类型检查及构建通过。

本项仅解决站内自动催办，不表示完整 B7 Gate 或外部门禁/账号回收通过。
