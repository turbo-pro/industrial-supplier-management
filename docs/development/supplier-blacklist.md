# 供应商风险观察与限制

管理后台入口 `/suppliers/blacklist`，API 入口 `/api/supplier-blacklist`（兼容早期命名）。观察、限期限制和黑名单均为独立审批事实，不把低绩效等级自动转成处罚。申请记录供应商、理由和可选依据编号。单个租户内同一供应商只能有一条待处理申请；已批准的观察可以与后续更强的限制并存，历史驳回、解除记录保留。

状态：`DRAFT → SUBMITTED → APPROVED/REJECTED`。正式解除通过[独立解除审批](restriction-lifting.md)，原批准状态保持不变，新增解除结果使该条限制失效。旧直接撤销入口停用，`REVOKED` 仅保留历史兼容。申请人不能自审；读取遵循供应商数据范围，写入需要对应动作权限。

限制批准后，供应商档案状态不变，但新增业务被阻断。新增业务与批准操作按供应商行串行化。解除仅排除对应限制；其他限制、非 ACTIVE 档案仍阻止新增业务。历史合同、项目不自动终止，需独立处置。

准入创建、提交和批准使用同一个公开限制判定入口（准入允许草稿/有效/停用档案，但不允许已退出档案或生效限制）；申请人不能批准自己的准入申请。合同激活、项目开工/复工、人员和车辆设备登记、人员启用、设备投入使用、现场签到都在服务端复查有效供应商与企业限制。仅观察不阻断；限期限制到期后停止阻断。

业务入口按供应商行锁串行化，供应商与限制记录采用当前读，避免旧事务快照绕过刚生效的限制。现场签到还锁定并复查人员状态，不能用先前的 ACTIVE 快照替代当前资格。限制不自动终止历史合同或暂停项目；终止/取消、签退、人员离场、资产交接和整改仍可执行，避免清退被反向阻塞。

类型支持长期黑名单 `BLACKLIST`、限期限制 `TEMPORARY` 和观察名单 `WATCH`。限期限制必须填写起止日期，只有状态为 `APPROVED` 且当前中国业务日期落在闭区间内才阻断新增业务；到期自动不再阻断，无须后台定时任务，也不改写历史审批状态。到期后可再发起新申请。观察名单需审核，但不阻断新增业务；供应商档案列表显示“观察中”标记，解除后标记消失。观察与限制可以并存，且观察不替代正式限制审批。尚未纳入已有合同/项目的人工处置流程和租户时区配置；首版业务日期固定为 `Asia/Shanghai`，避免应用与 MySQL 时区不同造成午夜判断不一致。
