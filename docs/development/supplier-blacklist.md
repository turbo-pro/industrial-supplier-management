# 供应商风险观察与限制

管理后台入口 `/suppliers/blacklist`，API 入口 `/api/supplier-blacklist`（兼容早期命名）。观察、限期限制和黑名单均为独立审批事实，不把低绩效等级自动转成处罚。申请记录供应商、理由和可选依据编号。单个租户内同一供应商只能有一条待处理申请；已批准的观察可以与后续更强的限制并存，历史驳回、解除记录保留。

状态：`DRAFT → SUBMITTED → APPROVED/REJECTED`，已批准可附理由撤销为 `REVOKED`。申请人不能审批自己的申请；审批、撤销均要求版本号，操作写入不可覆盖的事件及审计日志。读取遵循供应商数据范围，写入需要对应动作权限。

批准后，供应商档案本身状态保持不变，但有效性查询立即排除该供应商，禁止新建合同和项目、禁止重新启用已停用档案。新建业务与批准操作按供应商行串行化，避免批准与签约并发时穿透。撤销后恢复准入资格，但原档案若不是 `ACTIVE`，仍须按档案流程启用。历史合同、项目不自动终止；这属于单独的处置决策。

类型支持长期黑名单 `BLACKLIST`、限期限制 `TEMPORARY` 和观察名单 `WATCH`。限期限制必须填写起止日期，只有状态为 `APPROVED` 且当前中国业务日期落在闭区间内才阻断新增业务；到期自动不再阻断，无须后台定时任务，也不改写历史审批状态。到期后可再发起新申请。观察名单需审核，但不阻断新增业务；供应商档案列表显示“观察中”标记，解除后标记消失。观察与限制可以并存，且观察不替代正式限制审批。尚未纳入已有合同/项目的人工处置流程和租户时区配置；首版业务日期固定为 `Asia/Shanghai`，避免应用与 MySQL 时区不同造成午夜判断不一致。
