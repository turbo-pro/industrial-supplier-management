# 供应商退出前业务处置

供应商档案列表的“退出检查”展示待处置数量。`GET /api/suppliers/{id}/exit-readiness` 返回检查项；真正退出仍使用原有状态接口，必须填写原因并带版本号。

- 合同 `DRAFT/ACTIVE` 阻止退出，须终止或完成；`EXPIRED` 为结束态。
- 项目 `PLANNED/ACTIVE/SUSPENDED` 阻止退出，须取消或完成。
- 人员非 `EXITED` 状态阻止退出，须完成离场。
- 车辆、设备、工器具未交接离场均阻止退出（含待验收和退役资产）。交接须填写接收人/单位、说明及版本号；使用中的资产须先结束使用，交接后不可重复交接或变更使用状态，原状态与历史记录保留。
- 现场记录尚未签退、质量不符合项或安全隐患尚未关闭，均阻止退出。
- 绩效改进计划 `OPEN/SUBMITTED/REWORK` 阻止退出，须经复核验收至 `ACCEPTED`。已退出供应商不得新增改进计划；创建计划与退出共用供应商行锁。
- 前端预览不是授权依据；后端在退出事务中重新检查，并与新增合同、项目共用供应商行锁。
- 历史记录保留，`EXITED` 不可恢复；不自动终止合同、取消项目，不代替人工处置决策。

各模块实现 `SupplierExitCheck` 公开接口，供应商模块不直接查询外部表。未配置检查提供者时拒绝退出。新增人员、资产与退出共用供应商行锁；检查使用当前读。检查不自动关闭任何事项。应付款结清尚未纳入，不能将本轮视为完整 B7 验收。资产退役不等同于交接离场，不能通过强制退役代替交接。

交接接口：`POST /api/resources/assets/{id}/handover`，复用 `resource:asset:status` 权限并检查数据范围；交接结果在资产台账显示，记录操作人、时间并写审计。V30 不自动为历史资产生成交接记录，升级后需逐项确认。
