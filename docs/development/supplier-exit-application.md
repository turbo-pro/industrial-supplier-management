# 正式退出申请：本地业务关闭

管理入口：供应商档案 → 退出流程。范围为租户内供应商企业档案；现阶段尚无独立合作关系或工厂范围退出模型，不能据此宣称支持局部退出。

## 业务状态与规则

- 支持正常退出与淘汰，不开放紧急淘汰、强制完成或人工勾选跳过核验。
- 提交即为 `SUBMITTED`，允许存在待处置事项；同租户供应商最多一个待处置申请。依据文件必须有效，处置检查初始数量保留。
- 申请提交后阻止新准入、新合同项目、开工复工、资源登记启用及现场签到；已存在业务仍可终止、离场、交接、签退及整改。驳回或本人撤回解除这一申请的阻断，不解除其他限制。
- 重新核验从业务模块读取当前事实，不接受前端传入“已完成”。更新当前数量和应用版本、保留初始数量与事件；过期版本拒绝写入。
- 非申请人独立审批。批准重新核验全部检查和依据文件，不信任页面或提交时快照；任一模块缺失、重复检查代码、无效数量或财务未知均拒绝放行。
- 本地核验通过后，申请成为 `BUSINESS_CLOSED`，供应商成为不可恢复的 `EXITED`，独立结果范围为 `LOCAL_BUSINESS`。审批、状态变化、结果与事件在同一事务提交。
- 结果中的 `accessRecoveryStatus=NOT_VERIFIED` 明确表示外部账号、门禁和接口凭证尚未核验；不是“完整清退成功”。不能通过此页面伪造回执。

## 数据与 API

V35 创建 `sup_exit_application/item/result/event`，保留申请、初始及当前处置数量、批准事实和操作历史。结果按租户供应商与申请唯一；不提供普通删除或覆盖终态接口。

`/api/suppliers/{supplierId}/exit-applications` 支持创建、分页列表，`/{id}` 读取详细处置项与事件，`/{id}/recheck|cancel|review` 分别重新核验、本人撤回和审批。

权限：`supplier:exit:view/create/recheck/review/cancel`。同时遵循 `supplier:master` 数据范围；锁定供应商后再次检查当前归属范围。迁移不自动给生产角色授权。

创建、核验、撤回、批准与新增业务共用供应商行锁。新增业务检查退出申请使用当前读，避免事务旧快照绕过已提交申请。启用档案也检查待退出申请及当前有效限制。

## 必需检查能力

合同、项目、人员、资产交接、现场签退、安全隐患、质量不符合项、绩效改进及财务。财务使用 `OPEN_FINANCIAL` 或阻断项 `FINANCIAL_UNKNOWN`，未知不可能等同零事项。

当前处置项按检查代码聚合，不是逐合同/逐账号的移交台账；责任分派、计划生效时间、专项事故/索赔实体台账、文件归档、紧急处置、强制移交、合作关系/局部范围及外部回收任务仍待实现。审批当前为固定独立复核，尚未接入租户自定义多级退出流程。本地关闭不等同于企业全部退出事项完成。

## 验收范围

单测覆盖缺失检查、非法及重复结果、自审、过期版本、撤回权限、租户与当前组织范围、重复申请、核验版本及独立结果。

真实 MySQL 集成验证新申请阻断旧事务快照、驳回及撤回恢复资格、提交后出现新合同阻止批准、初始数量不变、重复审批拒绝、跨租户隔离，以及本地关闭与外部未核验状态区分。集成环境显式选择人工财务模式并提供已复核证据，不代表真实 ERP 集成。
