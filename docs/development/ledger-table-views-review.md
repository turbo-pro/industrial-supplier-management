# 合同与项目个人列方案验收

## 本轮交付

- 将 B2-07 个人方案扩展至 `contract.ledger`、`project.ledger`，继续使用 V37 的泛化表结构，无需新增迁移，也未修改任何历史迁移。
- 后端注册表同时约束表键、业务查看权限和允许列集合。合同需 `contract:view`，项目需 `project:view`，再叠加控制器统一 `table:view:manage` 权限。
- 合同目录：编号、合同/供应商、金额、期限、状态；项目目录：编码、项目/供应商、关联合同、计划周期、状态。编号/编码与名称必显，操作列固定保留。
- 新建、另存、版本化更新/删除、多方案切换和默认设置复用既有组件。相同用户三张表可保存同名方案及各自默认，取消合同默认不影响项目或供应商。
- 标签切换时使用显式组件 key 重建方案组件，不能复用上一张表的配置；表格列 key 保证顺序和宽度切换真正作用于列布局。
- 台账增加分页入口，查询/重置/标签切换回到第一页；列表请求序号与标签双重校验，防止旧响应覆盖新页。失败清空当前列表并提示，不误报为空查询成功。
- 新建项目合同下拉使用独立 `contractOptions`，不再覆盖合同台账列表；新建资料请求同样拒绝过期响应，切换标签关闭旧表单。
- OpenAPI 新增 `PersonalTableKey` 受控枚举并补齐三类业务列表 400/401/403 错误响应，客户端仍从唯一契约生成。

## 自动化及 Review 边界

新增两个后端测试：每张表只接受对应业务权限；新列目录拒绝隐藏标识及未知字段。扩展真实 MySQL 测试：三表同名/默认独立、跨表 ID 不可操作、错用列拒绝、取消默认不影响其他表。

客户端新增三个测试：合同/项目保存路径与请求体正确，以及合同权限失败按标准错误解码。此类客户端测试使用受控 mock，不冒充数据库或实际浏览器 E2E。

本轮没有改变合同/项目业务状态机、权限范围、导出或审批。原有本地业务限制仍由后端负责；个人列方案不产生权限或放行凭证。公共/租户级方案、其他业务表推广、持久化页面 E2E 仍未完成。

2026-09-27 验证：全量 bootstrap 集成 Profile verify 成功，列方案单测共 9 个（新增 2 个）、真实 MySQL 集成测试共 15 个（扩展三表隔离断言）无失败/错误/跳过。客户端测试共 4 个（新增 3 个）、客户端 TypeScript 构建、管理端 Vue 类型检查和生产构建通过。迁移仍回放 V1–V37。现有 Node 20.12 版本要求与大包警告保持原样，未修改机器环境或旧库 V25。
