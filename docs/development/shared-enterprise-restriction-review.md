# 企业级共享限制判定接口

## 交付与契约

`SupplierRestrictionEvaluator` 是供应商模块公开的企业级判定边界，返回 ALLOW/WARN/DENY、中国标准时间业务日期及不可变的全部命中列表。内部受控动作包含六类已落地动作及兼容旧调用的 GENERIC_NEW_BUSINESS；不允许客户端提供供应商状态或自由动作表达式。

`EnterpriseSupplierRestrictionEvaluator` 集中处理供应商生命周期状态、当前有效 BLACKLIST/TEMPORARY/WATCH、待处置退出申请及 DENY 优先级。所有限制与退出事实使用既有当前读 SQL，不另造一套规则。名称、原始限制原因和其他敏感信息不进入命中解释。

`SupplierReferenceService` 的 `activeForNewBusiness` / `eligibleForAdmission` 通过此接口拦截，新增 `eligibleForBusiness(supplierId,action)` 供业务模块逐步携带准确动作调用。已有合同/项目、人员资产、签到及准入调用保持兼容，不改动其业务权限或状态机。

解释接口也调用相同 evaluator，再映射成原 REST 响应；页面说明已更新。既有 API 路径、权限、响应字段、数据库结构保持不变，因此本轮无需新迁移或生成不同的 REST schema。

## 安全与事务约束

- evaluator 的方法名为 `evaluateLocked`：调用方必须先在业务事务中锁定并当前读供应商。两个生产调用点均保留此顺序；新增业务公开入口加 `@Transactional`，加入业务调用者事务。直接无事务调用底层 SPI 不属于受支持用法。
- 解释入口仍先校验供应商可见性，再锁后校验当前数据范围，之后读取命中及记录审计；不可见对象不读取限制事实、不生成解释审计。
- WATCH 返回 WARN，不阻断；企业限制或待处置退出返回 DENY。不存在的供应商返回不可用；未知生命周期状态、空动作或无效 ID 不能成为放行结果。
- 使用既有供应商锁保证限制审批/解除、退出及新增业务判定的并发顺序。没有关闭租户防护或数据库校验，也没有将旧快照转换成放行凭证。
- 绩效等历史业务使用的旧 `active()` 查询不改为新增业务拦截；继续允许既有处置路径。主档启用仍保持其独立状态转换核验，不将 generic ACTIVE 条件误用到 SUSPENDED→ACTIVE 转换。

## 自动化验收

新增七个动作参数化用例、一个空动作拒绝用例，以及四个 evaluator 用例：全部命中与不可变快照、准入/通用状态差异、非法输入不读数据、不完整实现结果不能成为允许。延用六个解释服务测试及全部原业务入口回归。

真实 MySQL 验收增加：观察名单在所有受控动作下不阻断；黑名单独立解除后，剩余临时限制在解释及全部受控动作下仍阻断。既有并发旧快照、合同/项目、资源、签到和退出测试继续执行。

前端验证是类型检查与生产构建，本轮不冒充持久化浏览器 E2E。查询审计仍是建议性快照，不是业务执行命中台账。

2026-09-27 验证结果：`./mvnw -q -pl backend/ism-bootstrap -am -Pintegration-test verify` 最终复跑成功，供应商单测 68 个（新增 12 个执行用例），真实 MySQL 集成测试 15 个，均无失败/错误/跳过。管理端类型检查和生产构建、`corepack pnpm check:api` 通过，REST 契约及生成文件无漂移。数据库仍只回放到 V37；旧本地库 V25 保持原状。既有 Node 20.12 引擎要求与大包警告未扩大处理范围。

## 后续边界

具体入口最新接入进展见 [动作路由验收](entry-action-routing-review.md)，不要仅根据本文件初次交付状态判断 generic 调用范围。

这是企业级共享接口，不是完整版本化规则引擎。组织/工厂/地点/品类范围、人员设备对象、REVIEW_REQUIRED、完整动作目录、所有入口准确动作上下文及业务拦截命中表仍缺失。旧 generic 调用保留以防回归，后续局部范围接入前必须逐入口补全上下文并做 Gate 回归；不能因为新增接口就宣布 B7-02/B7-03 整包完成。
