# 我的退出责任待办

## 业务边界

本轮接入 `/api/supplier-exit-tasks/mine` 和管理端 `/suppliers/exit-tasks`。直接读取退出实体、申请和供应商当前记录，不另建待办状态副本，不从消息反推。待办须同时满足当前租户、责任人为当前账号、事项 OPEN、申请 SUBMITTED、供应商未删除；重新分派、申请撤回/驳回/关闭和重新核验结清后，下一次查询即不再出现。

实体 OPEN 是最近核验快照，不意味着每次查询都重算全部业务。业务操作已结清但尚未重新核验时仍显示待办，页面明确提示最后核验时间并要求联系有权限人员重新核验。查询不会修改事项、审批或业务状态，没有手工完成命令。业务链接仅为台账入口，不声称精确定位具体业务详情。

## 权限、查询与页面

- 查看接口继续使用 `supplier:exit:view`，不会因为分派自动授予业务权限、查看权限或数据范围。
- 同一 SQL 的 count 和分页应用当前 `supplier:master` 数据范围：租户全部、组织集合、创建/归属本人；组织空集合、无范围、项目范围在没有供应商项目映射前均安全返回空。归属本人采用供应商已有的创建人作为归属人，与档案详情范围模型一致。
- tenant 条件覆盖三表关联；责任人取登录上下文，不接受调用方传入另一个责任人。只返回已授权供应商编号/名称、事项引用、说明和核验/分派时间，不包含人员证件或跨模块敏感字段。
- 按供应商编码/名称与八类事项筛选；通配符转义为字面值。最大关键词 100 字、页码 0–10000、每页 1–100，稳定按分派时间和 ID 倒序。
- count 和分页在只读事务中读取一致数据库快照。页面每页 20 条，切页/查询即清除旧行；请求序号保护并发查询，卸载废弃响应；组织切换刷新，仍按后端授权范围查询，不把前端组织选择器当作权限边界。
- V39 只注册供应商菜单下的待办入口，不自动扩张租户套餐、角色菜单或权限授权。已有租户需按既有 Console/角色菜单配置开通入口。
- 没有期限、逾期、自动催办、工作流人工任务聚合或强制移交；本轮并非完整 B7，也不是异步下载任务中心替代品。
