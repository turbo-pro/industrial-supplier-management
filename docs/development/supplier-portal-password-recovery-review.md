# 门户密码恢复：受控签发与一次性兑换

2026-10-22。本段提供管理员辅助恢复，不基于未验证邮箱自行发信，不实现短信/邮箱验证或外部身份校验，也不把管理员勾选视为软件完成了身份鉴定。

## 业务与验收边界

1. 部署 `ISM_PORTAL_PASSWORD_RECOVERY_ENABLED` 默认 false，且门户认证开关也必须启用。V74 新增 IAM 自有恢复凭证表和 SUPPLIER 模块独立权限 `supplier:portal:recover`；迁移不自动给现有角色增权。新租户的角色初始化沿用已有策略，部署方仍需检查角色分配。
2. 管理端在供应商账号列表按 `canRecover` 展示恢复入口，不能用主档修改权限替代恢复权限。后台读/签发/撤销均校验专用权限、租户、供应商数据范围和账号归属；签发另复核租户/套餐、供应商 DRAFT/ACTIVE、无待审退出及账号 ACTIVE。
3. 管理员先按企业既定可信渠道核实持有人，填写原因并明确确认 `identityVerified=true`；系统只记录声明和操作者，不声称已对接身份验证机构。禁止管理员填写用户的新密码。高风险场景的双人复核尚未实现，不能宣称有双人恢复审批。
4. 生成 32 字节安全随机数，43 位 URL-safe 凭证，有效 15 分钟，数据库只存 SHA-256 哈希。签发提升账号管理版本，替换旧 PENDING 凭证并审计同事务；明文只在成功响应返回一次，Cache-Control no-store，重读只给最近一条状态/时间/签发人，不给 token/hash/联系方式。
5. 签发本身**不**修改密码、不提升令牌版本、不撤销已有会话；怀疑账号被盗需先用已有停用/撤销会话流程。凭证遗失/响应丢失时，先刷新账号版本与最近状态，再显式重签替换，不能自动重放或取回旧明文。乐观版本阻止重复旧请求再次签发。
6. 可按最新账号版本与原因撤销尚未消费的凭证（含已过期或因版本变化失效、但物理状态仍 PENDING 的凭证），撤销与版本/审计同事务；已消费不回退。历史保留 REPLACED/REVOKED/CONSUMED；读取 PENDING 时根据当前账号版本/状态及到期时间显示 INVALIDATED/EXPIRED。
7. 门户未登录用户通过 `/api/portal/auth/reset-password` 提交凭证与新密码，绑定由凭证派生，不能指定租户、账号或供应商。与注册/登录共用已有传输来源限流。凭证不进入 URL、浏览器存储或审计；请求对象字符串脱敏。
8. 兑换独立 READ_COMMITTED 事务按平台租户→供应商→IAM 租户→账号→凭证锁序核验。凭证绑定签发时的管理版本和令牌版本，停用/恢复/撤销会话、自助改密、重新签发、人工撤销或退出后均不能绕过；待审退出也阻断，撤回后未变版本且未过期的凭证可继续核验。
9. 新密码沿用强度规则，最多 72 UTF-8 字节，不得与旧密码相同；弱/同/超限密码不消费凭证。成功时消费凭证、替换密码哈希、清空错误锁定、提升双版本、撤销全部会话及本人恢复审计整笔提交。并发兑换仅一方成功，后续重放拒绝，不返回登录令牌。
10. 门户显示恢复表单、规则及所有旧会话撤销提示，成功后新密码登录。网络结果未知时清除本页凭证并提示先用新密码核查，不自动再次兑换。管理员页面默认隐藏明文，读取失败不是空态；异常结果阻止重复写入，关闭后不可再读明文。

## 层次与接口

供应商模块授权并锁供应商后，仅经公共 `PortalPasswordRecoveryAdministration` SPI 调用 IAM；不跨模块读 Mapper。匿名定位器仅精确哈希找绑定，之后操作均走有 tenant_id 的 Mapper。账号、邀请和恢复凭证身份域不混用，恢复不等于账号重新启用、供应商重新准入或外部权限回收。

- GET/POST `/api/suppliers/{supplierId}/portal-accounts/{id}/password-recovery`：最近状态/一次性签发。
- POST 同路径 `/revoke`：人工撤销。
- POST `/api/portal/auth/reset-password`：匿名能力凭证兑换，仅此 POST 放行；不开放任何按邮箱/用户名枚举账号或自动发送凭证的入口。
- 原账号列表增加 `canRecover`，OpenAPI/生成客户端同步。页面沿用 Vue 3/Element Plus；UI/UX 技能用于确认、可见错误、加载与凭证保密反馈，不改既有主题和用户未提交的 UI。

## 复现与待补

集成：`./mvnw -q -pl backend/ism-bootstrap -am -Pintegration-test -Dit.test=PortalAuthIT,PortalInvitationIT,PerformanceMigrationUpgradeIT -Dfailsafe.failIfNoSpecifiedTests=false verify`。

真实跨端：`node scripts/verify-reminder-e2e.mjs --portal-recovery`，JDK 17+、Docker、项目要求的 Node/pnpm 与 Chrome。编排独立库、随机端口后端/管理端/门户及真实员工角色，先执行既有门户基线，再经页面签发→替换→撤销→重签→门户兑换→新密码登录。核对旧凭证/旧会话重放拒绝、只读员工直写 403，以及最终数据库三条凭证状态、双版本、会话与审计操作者。仅隔离夹具启用恢复；不改变部署默认值。

后续仍缺：真实响应丢失/断网恢复浏览器场景、跨组织细粒度恢复政策/双人审批、可信身份核验渠道集成、邮箱/短信验证与通知、恢复凭证历史分页及保留清理。现有状态只读入口不是完整审计查询页面。外部连接器、历史退出补偿执行及剩余锁序仍未完成。禁止以本段宣称完整 B3/B7 验收。
