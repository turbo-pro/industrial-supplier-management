# 供应商绩效评价

管理入口 `/performance/evaluations`。单个租户的供应商按评价周期形成唯一评分卡；分项为质量、交付、安全、服务。默认权重为 35/25/25/15，租户可在页面调整，合计必须为 100。

## 可验收规则

1. 只有有效供应商可以创建评价；周期结束日期不得晚于当前日期。相同租户、供应商、起止日期只能有一条评价。
2. 四个维度必须各出现一次，每项分数为 0–100、最多两位小数，且有评分说明和当前租户有效证据文件。总分由后端按权重计算并四舍五入到两位小数；A≥90、B≥80、C≥70、D<70。
3. 创建时复制租户当前权重到评分明细；以后修改租户权重不改变旧评分卡。驳回后编辑仍沿用原权重。
4. 评价时保存该供应商在周期内质量不符合项及安全隐患的总数、未关闭数。事实快照用于解释评分，不自动生成交付或服务分数；提交者应结合证据填写分项分数。
5. 状态为 `DRAFT → SUBMITTED → APPROVED/REJECTED`；驳回必须有理由，驳回后可编辑并重新提交。评价创建者不能审核自己的评价；审核通过后不得修改。
6. 所有读取和写操作受租户及 `performance:evaluation` 数据范围约束；修改使用版本号。历史操作保留事件记录，任何评分卡都可单独查询明细和处理历程。

此版未自动影响供应商准入、限制或黑名单；这些结果应在后续限制策略中明确阈值和审批责任，不把一个绩效等级直接解释为处罚决定。

## 绩效改进闭环

已批准评价可创建一份改进计划，记录根因、改进措施和不早于当前日期的期限。计划状态为 `OPEN → SUBMITTED → ACCEPTED`；验收不通过时走 `SUBMITTED → REWORK → SUBMITTED`。提交改进结果必须写完成说明并关联当前租户可用的证据文件；计划创建人不能验收自己的结果。所有变更校验版本号并写入事件与审计，历史记录不可覆盖。改进计划不自动改变供应商状态，限制与黑名单仍需独立审批。
